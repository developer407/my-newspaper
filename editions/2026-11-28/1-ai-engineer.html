Claude Fable 5.2 and Mythos 5.2: $8/$40 per million tokens, FrontierCode 2.0 at 49.1% (older, Nov 9)

Anthropic · Nov 9, 2026 (outside the 48-hour window, kept because it is the current flagship)

Anthropic upgraded Claude Fable and Claude Mythos, which are the same underlying model. Fable 5.2 (API id claude-fable-5-2) is open to everyone with strong cyber and biology safeguards; Mythos 5.2 has fewer restrictions and is gated to vetted organisations. Standard price is $8 per million input tokens and $40 per million output tokens, with an optional fast mode at $16/$80.

💡 Why it matters to you: Anthropic itself says Opus 5.5 is still the sensible default for most coding work. Treat Fable as the escalation tier in your Spring AI model router, not the everyday model.
Read deeper

On Anthropic's own table, Fable 5.2 scores 49.1% on FrontierCode 2.0 (agentic coding, Xhigh effort) against 45.5% for Opus 5.5, 69.9% on FrontierSWE v2 against 62.3%, and 89.3% on OSWorld 2.1 against 87.2%. Introducing Claude Ship: Code Review, PR Steward and policy-based approvals for pull requests

Claude resources · Nov 23, 2026

Claude Ship covers what happens after a PR is opened. Code Review is generally available, while PR Steward (keeps PRs green by answering failing CI, conflicts and review feedback) and Claude Approvals (auto-approves routine changes under a policy file in your repo) are in beta. It is on Team and Enterprise plans for GitHub repositories, and /ship in Claude Code starts the loop.

💡 Why it matters to you: This is the review-and-merge half of the AI coding workflow. If you teach or run a small team on GitHub, a policy file that says what Claude may approve is the part to study.
Read deeper

Anthropic reports that on the Claude Code team, merged PRs more than doubled from June to September while the share of reverted changes fell by more than 40%. PR Steward is designed not to approve or merge on its own, and Approvals starts in an observe-only mode before you enforce it through branch protection.

Limits: it is not available to organisations on Zero Data Retention, the HIPAA configuration or customer-managed keys. Billing is by tokens, a policy that uses Claude's review triggers a billed review even in observe mode, and admins can set spend limits. Anthropic's own page says it may miss bugs and security issues.

The enterprise guide to securing coding agents: sandbox, managed deny rules and a two-week pilot

Claude resources · Nov 23, 2026

Anthropic's guide lists six questions to ask of any coding agent, from "are actions checked outside the model" to "can you reconstruct an incident". It then maps four agentic risks (leaked credentials, unvetted dependencies and extensions, data exfiltration, prompt injection) to concrete Claude Code settings.

💡 Why it matters to you: Prompt injection and over-permissioned agents are the issues Indian enterprise buyers now ask about. This is a ready checklist for a security questionnaire or a conference talk.
Read deeper

Settings it names include sandbox.enabled, sandbox.network.allowedDomains, failIfUnavailable, allowUnsandboxedCommands set to false, allowManagedHooksOnly and allowManagedMcpServersOnly. Evaluation order for permission rules is deny, then ask, then allow, and managed deny rules cannot be overridden locally.

The pilot advice is plain: pick a low-sensitivity active repo, deploy a strict baseline, hold the policy fixed for two weeks, then review classifier denials and blocked egress and add allowlist entries rather than loosening deny rules. One caution from the guide: set onFailure to "block" on hooks, because the default lets a call through when the hook fails.

{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false,
    "network": { "allowedDomains": ["api.github.com", "repo.maven.apache.org"] }
  }
}

Docker: "Prove your AI agent guardrails work" with network, filesystem, credential and MCP policies

Docker blog · Nov 25, 2026

A Docker Captains post argues that guardrails must live outside the model and be tested with blocked-action checks plus matching audit records. It walks through Docker AI Governance (network, filesystem, managed credentials and MCP policy) with a bank-logs demo using the sbx CLI.

💡 Why it matters to you: Whatever agent you build with Spring AI or LangGraph, the lesson transfers: deny-by-default egress and read-only mounts beat prompt instructions every time.
Read deeper

The post cites two July 2026 incidents: a Grok Build CLI test where about 5.1 GiB of a 12 GB repo was uploaded before capture stopped, and an agent with Full Access that deleted most of a Mac's files. It also notes that after one plugin blocked rm, an agent fell back to unlink and find -delete, so blocking single commands is fragile.

Policy facts worth knowing: deny beats allow, local rules cannot grant more than org policy, filesystem changes need sandboxes recreated, and managed credentials only cover proxy-managed secrets, not tokens left in env vars. It also notes India's DPDP breach duties are scheduled to take effect in May 2027.

sbx policy ls --wide
sbx create --name bank-demo shell "$HOME/sbx-bank-demo/workspace"
sbx exec bank-demo curl -fI --max-time 15 https://example.com   # expect 403
sbx policy log bank-demo

Anthropic on building strong safety evaluations: pair harmful and benign prompts, go multi-turn, validate the grader

Anthropic research · Nov 13, 2026

A practical guide from Anthropic's own evaluation work. It says to match the design to the question, measure both harm and over-refusal, use multi-turn scenarios, calibrate the grader against human labels and report confidence intervals instead of single scores.

💡 Why it matters to you: Most of this applies to your own RAG or agent evals, not just safety. A paired set of good and bad cases stops a model from scoring well by refusing everything.
Read deeper

Concrete numbers: about 100 items as a minimum for complex multi-turn evals and about 1,000 for simple single-turn ones, with each case run several times. Use atomic binary grading criteria, hide design metadata from the grader, check length and position bias, and compare grader-human agreement against human-human agreement.

It also recommends preregistering metrics and comparisons before seeing results and running evals on snapshots during development, not only before release.

"The components of agent memory": transcripts, notes, wikis and an offline "dreaming" pass (older, Nov 6)

Anthropic research · Nov 6, 2026

Anthropic describes agent memory as four layers: transcripts, memory notes, structured representations such as wikis, and a small injected context. An offline "dreaming" pass reviews logs to fix wrong notes, merge duplicates and decide what gets preloaded.

💡 Why it matters to you: If you build long-running agents on Spring AI or LangGraph, this is a design for memory that is better than "append everything to a vector store".
Read deeper

Findings: on a 350,000-file corpus, wiki-only accuracy grew from 13% to 48% over 128 dreaming sessions, and wiki plus search reached 61% against 53% for search alone. Rigid rules such as "record only failures" hurt strong models, and a wrong note in the injected layer is carried into every session, so keep that layer small and link out.

Claude Code's auto memory loads only the first 200 lines or 25 KB of its index file. The post points to cookbooks for dreaming and for a knowledge-wiki quickstart. It pairs well with Craig Walls' Spring AI "When Agents Dream" recipe, covered earlier this week.
