Security

Todoist MCP server: DNS rebinding lets any website call its tools (CVE-2026-76807, CVSS 9.3)

GitHub Advisory GHSA-833v-v58w-294h · Nov 19, 2026

The optional self-hosted todoist-mcp-http server accepted browser requests without checking Host or Origin headers. A malicious website could use DNS rebinding to reach a victim's local 127.0.0.1 server and call tools that act on Todoist with the server's own API key. Versions up to 10.3.2 are affected and 10.3.3 fixes it.

💡 Why it matters to you: Any local HTTP MCP server you write has the same trap. Validate Host and Origin, or use stdio, which a browser cannot reach.
Read deeper

The reporters demonstrated creating and completing a task and said other write operations, such as updates, deletions, comments and labels, use the same path. The stdio entrypoint is not affected.

The advisory's fix guidance is strict Host and Origin validation, a per-run local bearer token and the DNS-rebinding protection in the MCP SDK. For Spring AI MCP servers, bind to localhost only and add the check at the filter level.

// Sketch: reject requests whose Host is not the one you expect
if (!Set.of("localhost:8080", "127.0.0.1:8080").contains(request.getHeader("Host"))) {
    response.sendError(403); return;
}

React Server Components: unauthenticated RCE in the react-server-dom packages (CVE-2026-126187, CVSS v4 9.5)

GitHub Advisory GHSA-xqc2-xf4c-x3h3 · Nov 10, 2026 (older)

Crafted payloads sent to frameworks that support RSC can lead to remote code execution, in rare cases where responses carry several typed arrays plus an attacker-controlled value. react-server-dom-webpack, -parcel and -turbopack are affected from 19.0.0 through 19.0.8, 19.1.0 to 19.1.9, 19.2.0 to 19.2.8 and 19.3.0. Patched versions are 19.0.9, 19.1.10, 19.2.9 and 19.3.1.

💡 Why it matters to you: If you use Next.js or another RSC framework, update React packages now. Apps with no server, or no framework or bundler plugin that supports RSC, are not affected.
Read deeper

The weakness is classed as unsafe deserialisation (CWE-502). The advisory lists no workaround and recommends upgrading immediately. The 19.x patch releases of Oct 14, titled "Improve transport protocol", are the fix.

A plain Vite SPA with Spring Boot on the backend is not affected, but check the lockfile for react-server-dom-* if you adopted a framework.

npm ls react-server-dom-webpack react-server-dom-parcel react-server-dom-turbopack
npm i react@19.3.1 react-dom@19.3.1

Three more MCP servers get advisories in 48 hours: markdownify-mcp SSRF, bigcommerce-api-mcp with no auth, bagel-mcp SQL execution

GitHub Advisories · Nov 26 and Nov 27, 2026

markdownify-mcp (before 1.2.0) has an SSRF where URL validation can be bypassed with DNS names or IPv6 forms, reaching loopback, internal hosts and cloud metadata (CVSS 8.3). bigcommerce-api-mcp (before 1.0.1) skips authentication on its /sse and /messages routes (CVSS 8.7). bagel-mcp (before 2.5.5) exposes unsandboxed DuckDB SQL through a "read-only" tool (CVSS 7.7).

💡 Why it matters to you: MCP servers are small, fast to write and often shipped without a security pass. Treat every third-party MCP server as untrusted code with network access.
Read deeper

The common patterns: a tool that fetches a URL without blocking private ranges, a transport that forgets the auth middleware, and a "read-only" annotation that is not enforced. The same GitHub list shows more MCP advisories from the same days, including SSRF in mcp-video-analyzer and Wazuh-MCP-Server and an access-control bypass in WhoDB.

Practical checks: pin versions, run servers in a sandbox with an egress allowlist, and do not trust tool annotations as a security boundary.

  • Related: GHSA-wg5w-425h-9fvm (bigcommerce-api-mcp)
