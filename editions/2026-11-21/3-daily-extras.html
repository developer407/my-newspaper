AI tools of the day

Tool: chrome-devtools-mcp, Chrome DevTools for coding agents

ChromeDevTools/chrome-devtools-mcp · trending this week (about 3.3k stars gained; 58.6k total, Apache-2.0)

chrome-devtools-mcp is an MCP server, plus a CLI, that lets a coding agent control and inspect a live Chrome browser. It supports performance tracing, network and console debugging, screenshots and browser automation built on Puppeteer. A --slim flag exposes a reduced tool set for basic browser tasks.

💡 Why it matters to you: Point an agent at your React app on localhost and let it read console errors, check network calls to your Spring Boot API and take screenshots, instead of copying logs by hand.
Read deeper

It needs Node.js LTS and a current stable Chrome. Add the server to any MCP client with the config below; the README's tool reference lists the full tool set, which the page did not enumerate.

Treat a browser-controlling agent like any other powerful tool: run it against local or test sites, and do not leave signed-in sessions open in the controlled Chrome.

{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}

Tool: CodeGraph, a local code knowledge graph that cuts file-by-file searching for coding agents

colbymchenry/codegraph · trending today (about 151 stars today; 78.3k total, MIT)

CodeGraph parses your code with a native Rust parser and tree-sitter grammars into a local SQLite graph of symbols, calls, imports and inheritance, kept in sync by a file watcher with a debounce of about two seconds. Its MCP server exposes one main tool, codegraph_explore, which returns relevant source, call paths and impact information in one call. It runs entirely locally with no API keys.

💡 Why it matters to you: On a large Spring Boot repo an agent can ask 'what calls this service method?' without reading dozens of files, which saves tokens and time.
Read deeper

The project reports its own benchmarks of fewer tool calls and lower token use than file-by-file search, but these figures are self-reported, so test on your own repo before believing them. It supports 20+ languages including Java, Kotlin and TypeScript, and many agents such as Claude Code, Cursor, Codex CLI, Gemini CLI and GitHub Copilot.

The index lives in a .codegraph/ folder, so add it to .gitignore before committing.

npm i -g @colbymchenry/codegraph
codegraph install      # wire up your agents
cd your-project
codegraph init          # index this project

Tool: Modern Web Guidance, skills that keep your coding agent on current web best practices

GoogleChrome/modern-web-guidance-src · trending this week (about 5.2k stars gained; 9.6k total, Apache-2.0)

Modern Web Guidance is a set of skills covering 262 modern web features and 204 real-world use cases, aimed at steering agents away from legacy patterns and bloated JavaScript towards native platform APIs. A CLI feeds targeted guidance into the agent's context: search finds guides, retrieve fetches one by ID, and legacy-scan checks a codebase for patterns to modernise. It requires Node.js 22 or later.

💡 Why it matters to you: Agents trained on older code often write outdated React and CSS patterns, and this gives you a cheap way to keep generated front-end code current.
Read deeper

Run the install wizard in a project, then ask your agent to run legacy-scan and propose changes. Review each change: a guidance library reduces outdated suggestions but does not replace code review.

Because the repository is large, the fetch only read part of the README; check the repo for the full list of supported agents.

npx modern-web-guidance@latest install

Tool: GitHub Spec Kit, spec-driven development with slash commands for your agent

github/spec-kit · trending today (about 166 stars today; about 150.8k total, MIT)

Spec Kit is GitHub's open source toolkit for spec-driven development. In your agent's chat you run /speckit-constitution once for project principles, then /speckit-specify to describe what to build and why, /speckit-plan for the technical approach, /speckit-tasks to break it down and /speckit-implement to build it, repeating /speckit-converge until it reports Converged. It needs Python 3.11+, uv and a supported coding agent.

💡 Why it matters to you: Writing the spec first gives you a clean structure for tutorial projects, and a record of decisions you can turn into video chapters.
Read deeper

The README's examples use GitHub Copilot and link an integrations index for other agents. It also includes bug-fixing and idea-assessment workflows besides the main one.

Try it on a small Spring AI feature, such as the decision-model triage service idea below, and compare the result with a plain prompt.

uv tool install specify-cli
specify init my-project --integration copilot
cd my-project

GitHub repos of the day

Repo: embabel/embabel-agent, goal-directed agents on the JVM and Spring

embabel/embabel-agent · Apache-2.0 · about 4.6k stars; latest release 1.5.4 (Oct 28)

Embabel is a Kotlin framework with a Java-friendly API, built on Spring, for authoring agentic flows. You define agents with annotations such as @Agent, @Action and @AchievesGoal (or a Kotlin DSL), and the platform plans a sequence of actions toward a goal using GOAP by default, replanning after each step. Different models can be assigned to different steps, including local ones through Ollama, Docker or LM Studio, and it includes MCP client and server support, A2A support and OpenTelemetry observability.

💡 Why it matters to you: It is the most Spring-native way to learn agent planning, and it works with typed domain objects you already know how to model.
Read deeper

Actions and goals operate on strongly typed domain objects, so hand-written code and prompts work together, and agents are plain Spring beans that can be unit-tested with mocks. Its execution modes are Focused (code asks for a specific agent), Closed (intent selects an agent) and Open (the platform picks a goal and builds a plan).

Recent releases added decision and classification service contracts (1.5.4), agent process snapshot and restore for human-in-the-loop persistence (1.5.2) and MCP over Streamable HTTP (1.5.3). Spring AI Agent starts incubating in early December, so this is a good project to compare it against.

@Agent(description = "Summarise a person's horoscope")
public class HoroscopeAgent {

    @Action
    public Horoscope fetch(StarPerson person) {
        return new Horoscope("Today favours bold moves.");
    }

    @AchievesGoal(description = "Write a short, cheerful reading for the person")
    @Action
    public Writeup write(StarPerson person, Horoscope horoscope, Ai ai) {
        return ai.withDefaultLlm()
                 .createObject("Write a cheerful reading for " + person.name()
                         + ": " + horoscope.summary(), Writeup.class);
    }
}

Repo: microsoft/markitdown, turn PDFs, Word, Excel and more into Markdown for LLM pipelines

microsoft/markitdown · MIT · about 197.3k stars; trending today (+281)

MarkItDown converts PDF, PowerPoint, Word, Excel, images (EXIF and captioning), audio (EXIF and transcription), HTML, CSV, JSON, XML, ZIP files, YouTube URLs and EPub into Markdown. The README says the output is meant to be consumed by text-analysis tools rather than for high-fidelity human reading. A markitdown-mcp package is in the repo, and it needs Python 3.10 to 3.14.

💡 Why it matters to you: It is the quickest ingestion step for a RAG tutorial: convert a folder of documents to Markdown, then chunk and embed into pgvector with Spring AI.
Read deeper

Image captioning and speech transcription rely on web-hosted services, so keep sensitive files out of those paths. The Python API takes a path and returns an object with a markdown field.

Compare its output with Apache Tika, which Spring AI's TikaDocumentReader uses; Spring AI 2.1 now caps Tika extraction at 10,000,000 characters by default.

pip install 'markitdown[all]'
markitdown path-to-file.pdf -o document.md

# Python
from markitdown import MarkItDown
md = MarkItDown(enable_plugins=False)
result = md.convert("test.xlsx")
print(result.markdown)

Repo: SWE-agent/mini-swe-agent, a coding agent in about 100 lines of Python that only uses bash

SWE-agent/mini-swe-agent · MIT · about 9.9k stars; trending today (+66)

mini-swe-agent is a minimal software engineering agent from the SWE-agent team. The agent class is about 100 lines, it uses only bash as its tool without the model's tool-calling interface, each action runs independently through subprocess.run and the message history is linear. The project claims above 74% on SWE-bench Verified, and it works with many models through LiteLLM, OpenRouter and Portkey.

💡 Why it matters to you: Reading 100 lines of agent loop teaches more than any framework diagram, which makes it a great base for a 'build an agent from scratch' video.
Read deeper

It supports local execution, Docker or Podman, Singularity or Apptainer and Bubblewrap, so you can choose how much isolation to run it with. The benchmark number is the project's own claim and depends on the model used.

Pair it with the Spring AI tool-confirmation features: both are about deciding what an agent may run, one at framework level and one as a tiny loop.

pip install uv && uvx mini-swe-agent
# or
pip install mini-swe-agent

Idea: a support-ticket triage service with Spring AI Decision Models, sessions and approvals

Built from the Spring AI 2.1.0 GA release (Nov 20, 2026)

Build a Spring Boot service that reads an incoming support message and answers typed questions with probabilities: is it a defect, which team owns it, how urgent is it. Use the new DecisionModel with a confidence threshold, the Session API to keep each customer's history separate, and tool-call confirmation before any refund or email is sent. Show the decisions in a React inbox with an approve or edit button.

💡 Why it matters to you: It uses most of the new Spring AI 2.1 features in one realistic app, and the React approval inbox makes a good full-stack tutorial.
Read deeper

Start with Ollama and the default decision model, which needs no API key, then swap in OpenAI for comparison. Log each decision's probability so you can plot how many go to human review at 0.8, 0.9 and 0.95.

Stretch goals: add the modular RAG pipeline for answering from a help centre, and track cost per ticket in Langfuse.

Learn today: stop NoSQL injection in an Express and Mongoose API with sanitizeFilter and a strict Zod schema

Prompted by Mongoose 9.12.2 and 8.24.10 (Nov 16, 2026) and the MongoDB Node driver 7.9.1 security fixes

NoSQL injection happens when a request body like {"email": {"$ne": null}} reaches a query filter and matches every user. Two cheap defences stack: validate the body shape with a strict Zod schema so operators never arrive, and turn on Mongoose's sanitizeFilter as a safety net. This week's Mongoose release closed a bypass of sanitizeFilter that used top-level fields starting with $, so update first.

💡 Why it matters to you: It is a ten-minute fix that every MERN project you teach or ship should have, and it makes a good short video.
Read deeper

Order of work: update mongoose and the mongodb driver (7.9.1 or newer), set sanitizeFilter globally, then validate every request body with .strict() so unknown keys fail. Test with curl using a body such as {"email":{"$ne":null},"password":"x"} and expect a 400.

Sanitising removes dangerous operators but is not a replacement for schema validation, and it does not protect other query builders you might use, such as raw aggregation pipelines.

import express from 'express';
import mongoose from 'mongoose';
import { z } from 'zod';

mongoose.set('sanitizeFilter', true);

const LoginBody = z.object({
  email: z.string().email(),
  password: z.string().min(8),
}).strict();

const app = express();
app.use(express.json());

app.post('/login', async (req, res) => {
  const parsed = LoginBody.safeParse(req.body);
  if (!parsed.success) return res.status(400).json({ error: 'invalid body' });

  const user = await User.findOne({ email: parsed.data.email });
  // ...compare the password hash here
  res.sendStatus(user ? 200 : 401);
});
