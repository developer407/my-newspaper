Spring AI Session API replaces ChatMemory with an append-only event log

spring.io blog · Nov 20, 2026

The new Session API stores a conversation as an append-only event log with turn-aware compaction, keyword recall through searchEvents, and a JDBC repository. Advisors hold no state, so any instance of your service can serve any turn, and there is deliberately no default session, which stops histories from different users merging. ChatMemory, its advisors and repositories are deprecated for removal in 3.0.0.

💡 Why it matters to you: If your chatbots use ChatMemory today, this is the migration path, and the per-user session id is the right habit for any multi-tenant AI app you teach.
Read deeper

Because the log is append-only, compaction works on whole turns instead of rewriting history, and recall can search past events by keyword through a tool the model can call. The post shows the session id flowing in two places: the SessionAdvisors advisor and the tool context, so recall tools know which session to search.

The older Spring AI Session community project is being archived in favour of the core API, while Spring AI Session Extensions continues with new repositories, including one for Kafka. More session repositories for other stores are planned before 3.0.0.

String answer = chatClient.prompt()
    .user("What did we decide about the invoice?")
    .advisors(SessionAdvisors.session(sessionId))
    .toolContext(Map.of(SessionRecallTools.SESSION_ID_CONTEXT_KEY, sessionId))
    .call()
    .content();

Decision Models: typed yes/no, choice and score answers with probabilities

spring.io blog · Nov 20, 2026

Spring AI 2.1 adds a DecisionModel API for typed yes/no, choice and score questions, and every answer comes with a probability. Three providers ship: OpenAI, Ollama (default model d1-omni:600m, no API key needed) and System One. The same API now powers RAG reranking and filtering and tool search.

💡 Why it matters to you: Routing, triage and moderation steps no longer need a free-text prompt and brittle parsing, which makes classic AI SaaS features like ticket routing much easier to demo.
Read deeper

Instead of asking a chat model to answer in JSON, you declare questions with a text and what yes or no means, then read the result with a confidence threshold. In the post's example, isYes(0.9) only returns true when the model is at least 90% sure.

The older Spring AI TypeSafe project is being archived in favour of DecisionModel and a new Spring AI Decision Extensions project. Weaviate 1.41 RC1 (later in this edition) also lists reranking with decision models, so the idea is spreading beyond Spring.

DecisionResponse response = decisionModel.call(DecisionPrompt.builder()
    .text("My new headphones arrived yesterday, but the left side doesn't work. Can I get my money back?")
    .question("defect", YesNoQuestion.builder()
        .text("Does the customer report a defect?")
        .whenYes("Part of the item does not work as it should")
        .whenNo("The item works, and the message is about something else")
        .build())
    .build());

boolean defect = response.getYesNo("defect").isYes(0.9);

Tool-call confirmation, call limits and guardrail refusals: the agent-harness blocks in 2.1

spring.io blog · Nov 20, 2026

Tools can now be marked with requiresConfirmation = true, so the loop pauses, returns the pending calls and resumes after your decisions. Per-tool and per-turn call limits default to 40 and 150, and hitting one either throws ToolCallLimitExceededException or tells the model to stop. Blocked replies are marked as GuardrailRefusal, and ChatClient.entity(...) throws GuardrailRefusalException or ContentFilteredException.

💡 Why it matters to you: Human approval and hard limits are what separate a demo agent from one you can safely show a client, and they arrive as framework features instead of hand-rolled code.
Read deeper

A confirmation gate matters most for tools with side effects such as sending email, refunding a payment or running a command. This week's advisories on coding agents show why: an allowlist that auto-approved supposedly read-only commands let attacker-controlled text run programs. The pause-and-resume design lets a UI show the exact call before anything executes.

The sketch below shows the exception handling the post describes: because both refusal types are thrown from entity(...), one catch can return a safe fallback instead of a stack trace.

// sketch: names from the 2.1.0 GA post, imports omitted
try {
    Reply r = chatClient.prompt().user(question).call().entity(Reply.class);
    return r;
} catch (GuardrailRefusalException | ContentFilteredException ex) {
    return Reply.refused("I can't help with that request.");
}

Spring AI 2.1 fixes 13 CVEs: read the upgrade notes before you bump

spring.io blog · Nov 20, 2026

The CVE list covers an SSRF blocklist bypass in Bedrock Converse, the full prompt logged at WARN, unbounded Tika extraction, several denial-of-service issues, filter injection and tenant-isolation bypasses in Redis, Typesense and Coherence, and cross-user disclosure in the Redis semantic cache. The upgrade notes add behaviour changes: SemanticCacheAdvisor now needs a SemanticCacheScopeResolver bean, and TikaDocumentReader stops at 10,000,000 characters by default.

💡 Why it matters to you: If you run RAG with Redis or Tika in anything user-facing, treat this as a security upgrade, not a feature bump.
Read deeper

Spring AI 2.0.1 had already fixed seven CVEs and those are included in 2.1.0. The notes also say the Anthropic integration moves to Anthropic Java SDK 3.x with its own migration guide, and Typesense filter values are now written as backtick literals, with values containing a backtick rejected.

A practical order of work: pin Spring Boot 4.2 and Spring AI 2.1.0 together, add the semantic-cache scope resolver if you use that advisor, then run your RAG ingestion on a sample PDF set to see whether the new Tika limit trips.

Upgrade checklist (from the 2.1.0 notes)
1. Spring Boot 4.2 + Spring AI 2.1.0 together (or 2.0.3 on the 2.0 line)
2. Anthropic users: Anthropic Java SDK 3.x migration guide
3. SemanticCacheAdvisor: provide a SemanticCacheScopeResolver bean
4. TikaDocumentReader: default cap is 10,000,000 characters
5. Typesense: backtick-literal filter values
6. ChatMemory: plan the move to the Session API (removal in 3.0.0)

MCP 2026-07-28 in Spring AI: set the protocol to MODERN and cap your sessions

spring.io blog · Nov 20, 2026

Spring AI 2.1 can serve the stateless 2026-07-28 revision of the Model Context Protocol over WebMVC, WebFlux or STDIO by setting spring.ai.mcp.server.protocol=MODERN. Clients can mix legacy and modern connections, and a client-scope setting chooses whether a client is created per request, shared, or picked by your own bean. Tools, resources and prompts can change at runtime, and Streamable HTTP servers can cap sessions with maxSessions and sessionIdleTimeout.

💡 Why it matters to you: Your Spring Boot MCP servers keep working with older clients while you adopt the stateless protocol, and session caps are a cheap defence against resource exhaustion.
Read deeper

The underlying MCP Java SDK 2.2.0 (released Nov 16) added the stateless server and client in a new io.modelcontextprotocol.modern package and deprecated roots, sampling and logging, according to its release notes. Spring AI wraps that, so most of your work is configuration.

Spring AI 2.1.1 is planned for December with STDIO and WebClient MCP client transports, per the roadmap in the same post.

RAG, vector stores and evals

Deep dive: Spring AI modular RAG filters and reranks retrieved chunks, and why the GA changes the plumbing

spring.io blog · Oct 2, 2026 (notable deep-dive; 2.1 GA changes the decision-model part)

The post shows why a plain QuestionAnswerAdvisor falls short and builds a pipeline with RetrievalAugmentationAdvisor: an LLM rewrites the chatty question, a second call expands it into several queries, similarity search runs per query, then a filter and reranker keep only chunks that actually answer. In its Hurricane Milton example, six unique chunks came back, four were reference-list noise, and the two survivors scored 0.97 and 0.88.

💡 Why it matters to you: This is a ready-made structure for a RAG tutorial, including the prompt-injection check on retrieved text that most demos skip.
Read deeper

The filter asks four questions per passage with thresholds: prompt injection above 0.70 is excluded, a contradicting passage is kept but tagged, relevance below 0.45 is excluded, and evidence of an answer must be above 0.55. The post notes the pipeline adds two LLM calls before retrieval and one decision call per chunk, and that it fails open with a warning if the decision API is unavailable.

The demo uses the TypeSafe client, which the 2.1.0 GA post says is being archived in favour of DecisionModel, so expect to port the Jev filter and reranker classes to the core API.

var advisor = RetrievalAugmentationAdvisor.builder()
    .queryTransformers(RewriteQueryTransformer.builder().chatClientBuilder(ragClient).build())
    .queryExpander(MultiQueryExpander.builder().chatClientBuilder(ragClient).numberOfQueries(3).build())
    .documentRetriever(VectorStoreDocumentRetriever.builder()
        .vectorStore(vectorStore).similarityThreshold(0.5).topK(4).build())
    .documentPostProcessors(
        JevDocumentFilter.builder(typeSafeClient).build(),
        JevDocumentReranker.builder(typeSafeClient).topK(3).build())
    .queryAugmenter(ContextualQueryAugmenter.builder().allowEmptyContext(true).build())
    .build();

MCP and security

MCP's transport trust gap: the SDK advisories share one pattern, and the release notes show the fixes

Cloud Security Alliance research note, Nov 9, 2026 (read via search result, not fetched) plus MCP SDK release notes

A Cloud Security Alliance note says that between December 2025 and October 2026 the official MCP SDK maintainers published a series of mostly High advisories. Its examples include OAuth clients in the Python and TypeScript SDKs that could send client secrets and tokens to an attacker-chosen endpoint, and shared TypeScript transport instances that could route one client's responses to another. The release notes show the fixes: MCP Python SDK 2.2.0 follows redirects only within the same scheme, host and port, validates the authorization server issuer, expires idle sessions after 30 minutes and caps servers at 10,000 sessions.

💡 Why it matters to you: If you write MCP servers or clients in Spring, apply the same three habits: pin redirects, validate the token audience, and bound sessions.
Read deeper

Agentic RAG under a budget: papers on tool-call limits, token budgets and compressed tool schemas (older, search-sourced)

arXiv 2603.08877 (Mar 2026), 2605.26165 (2026) and 2602.19127 (Feb 2026), read via search snippets · slower topic

No fresh arXiv papers could be reached from this run, so this card points to three recent agentic-RAG papers found through search. One evaluates design choices under explicit tool-call and token budgets across six LLMs and three QA benchmarks, another shows that compressing tool schemas helps agentic RAG fit constrained context budgets (with a 28-tool benchmark called NovaTech-28), and a benchmark called AgenticRAGTracer has 1,305 data points and reports that even the best models score poorly on multi-step retrieval reasoning.

💡 Why it matters to you: Spring AI 2.1's default limits of 40 calls per tool and 150 per turn are exactly the kind of budget these papers study, so they give you a reason to tune them.
Read deeper

Takeaway for your own apps: log tool-call counts and tokens per question, set budgets lower than the defaults, and test whether a shorter tool description keeps accuracy. Compare against a plain retrieve-then-answer baseline, because the extra planning calls cost latency and money.
