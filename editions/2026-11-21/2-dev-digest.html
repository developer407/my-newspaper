Mongoose 9.12.2 and 8.24.10 harden sanitizeFilter after a bypass via MongoDB internal expressions

Automattic/mongoose releases · Nov 16-20, 2026

Mongoose 9.12.2 hardens sanitizeFilter so top-level fields starting with $ are caught, closing a bypass through internal expressions such as $_internalSchemaXor, and adds hardening for sanitizeProjection. The same fix is in 8.24.10 for the 8.x line. 9.12.3 (Nov 20) fixes Model.validate() pathsToSkip matching and update validators on mixed paths in subdocuments.

💡 Why it matters to you: NoSQL injection through request bodies is the classic MERN bug, and sanitizeFilter is the guard most tutorials recommend.
Read deeper

9.12.2 also keeps BigInts intact in addToSet(), casts $and, $or and $nor wherever they appear in array filters, and resets document state before retrying after a transient commit error.

Turn the option on globally, and still validate the shape of req.body with a schema such as Zod; sanitizing is a safety net, not a design.

import mongoose from 'mongoose';

// reject $-operators smuggled in through query filters
mongoose.set('sanitizeFilter', true);

Spring Cloud Kubernetes CVE-2026-59434: YAML in ConfigMaps and Secrets can instantiate arbitrary Java types

spring.io security advisory · Nov 19, 2026

Spring Cloud Kubernetes parses ConfigMap and Secret entries ending in .yaml with a SnakeYAML instance that has no safe constructor or type restrictions. If SnakeYAML older than 2.0 is on the classpath, someone who can write to a ConfigMap or Secret the app reads can supply a payload that instantiates arbitrary Java types. The advisory rates it Medium (CVSS AV:L/AC:L/PR:H) and lists CWE-502; the Spring Cloud release notes call it a remote code execution fix.

💡 Why it matters to you: If you deploy Spring Boot on Kubernetes with config from ConfigMaps, upgrade to 5.0.5 or move to the 2026.0.0 release train.
Read deeper

Affected: 5.0.0 to 5.0.4, 3.3.0 to 3.3.4 and 3.1.0 to 3.2.4. Fixed: 5.0.5 in open source, with 5.0.4.1, 3.3.5 and 3.2.5 only for Enterprise Support, and no free fix listed for 3.1.x.

The high privilege required (write access to the ConfigMap) lowers the risk, but anyone with namespace edit rights counts, so check your RBAC as well.

Etherpad pre-auth file read (CVSS 9.8) and XWiki HQL injection (CVSS 8.8): two self-hosted apps to patch

GitHub Advisory Database · Nov 2-20, 2026

Etherpad's /static handler has a path traversal that lets an unauthenticated user read any file the process can access (CVE-2026-114516, CVSS 9.8, fixed in 3.3.3) because backslashes are only normalised on Windows but later converted unconditionally, recreating ../ sequences. XWiki's query REST API allows HQL injection (CVE-2026-61689, CVSS v4 8.8, fixed in 16.10.18, 17.10.5 and 18.2.0), letting unauthenticated users extract database contents including password hashes in roughly 800 requests.

💡 Why it matters to you: Both are classic input-handling bugs, the same family as the path and query checks you write in your own Spring and Node APIs.
Read deeper

Etherpad's route runs before session and access-check middleware, so authentication settings do not help, and a reverse proxy forwards the encoded sequence unchanged. XWiki's patches disable HQL and WXQL queries in the REST API by default; until you upgrade you can block /rest/wikis/{wikiName}/query at the proxy.

If you self-host collaboration tools for a team or course, subscribe to their advisories instead of waiting for a CVE feed.

PyPI advisories (Nov 20): flyto-core arbitrary file write, ait-gui route-to-code-execution and amqtt DoS

GitHub Advisory Database (pip) · Nov 20, 2026

flyto-core has several: an arbitrary file write through unguarded data and file modules (CVE-2026-77312, Critical) and SSRF guard bypasses through DNS rebinding and unchecked pagination URLs (CVE-2026-77313, 77315 and 77316, High). ait-gui lets an unauthenticated route chain run Python in the server process (CVE-2026-77309, High), and amqtt has a QoS 2 memory leak and a regex denial of service (CVE-2026-130176 and 104199, High). svglib has exponential resource use from nested SVG use references (CVE-2026-132275).

💡 Why it matters to you: SSRF and DNS rebinding keep showing up in Python agent and automation libraries, so check any URL fetchers you give to an LLM.
Read deeper

The flyto-core SSRF items share a pattern: checking the resolved IP but then connecting by hostname, which a DNS answer can change between check and use. Resolve once, validate, and connect to the validated address.

Pin your dependencies and run pip-audit in CI, because several of these libraries are pulled in indirectly by agent toolkits.

pip install pip-audit
pip-audit -r requirements.txt

twilio/twilio-node releases · Nov 6 and Nov 18, 2026

Redux Toolkit 2.15.0: each store gets its own RTK Query middleware runtime, and removing a cache entry aborts its request

reduxjs/redux-toolkit releases · Nov 18, 2026

RTK 2.15.0 gives each store its own RTK Query middleware runtime so stores sharing one api no longer share state, makes initiate() promises resolve with their own request's result instead of stale data, and passes a startReason value to query functions and hooks. pollingInterval can be a function of the cache entry, and getRunningQuery and retainFor are added. Behaviour change: removing a cache entry while its request runs now aborts that request, so unwrap() can reject.

💡 Why it matters to you: If you fetch Spring Boot APIs through RTK Query, check any code that unwraps a query after resetting or removing cache entries.
Read deeper

2.14.0 (Nov 3) had added dispatch-path and listener-middleware speedups, cache entry selectors, entity adapter removeMany({ where }) and selectByIds, and RTK now ships its own Draft and Patch types so emitted declarations no longer reference Immer.

Dynamic polling is handy for dashboards that should poll fast while a job runs and slow down when it finishes.

Playwright 1.65 can run under Bun, adds a failures reporter and tightens cookie and proxy behaviour

microsoft/playwright releases · Nov 5 and Nov 13, 2026

Playwright 1.65.0 (Nov 5) lets the test runner run under Bun with --bun (no watch mode or async stack frames), adds a failures reporter and an onlyFailures option for the HTML, JSON and JUnit reporters, and a built-in exclusive test lock. Breaking changes: class fields follow useDefineForClassFields, actions wait for elements to be not inert, cookie matching follows RFC 6265, and proxy credentials are no longer sent to websites. Node.js 20 is no longer tested. 1.65.1 (Nov 13) fixes a decorated-class regression and ships Chromium 159, Firefox 159 and WebKit 27.2.

💡 Why it matters to you: End-to-end tests are the cheapest way to prove your React plus Spring Boot demo still works after every dependency bump this week.
Read deeper

The proxy-credentials change is a security improvement for tests that run behind a corporate proxy, and the cookie change can alter results for flows that depend on lenient cookie matching.

If you teach testing in tutorials, the failures-only reporter keeps CI logs short.
