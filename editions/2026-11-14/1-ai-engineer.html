Anthropic ships Claude Fable 5.2 and Mythos 5.2 — $8/$40 per million tokens

Anthropic · Nov 9, 2026

Anthropic released Fable 5.2 and Mythos 5.2, two flagships that share one underlying model. Fable is open to everyone; Mythos is gated to vetted orgs via the Cyber and Life Sciences Verification Programs. Anthropic says both are a step above Opus 5.5 on almost all evaluated capabilities, yet still recommends Opus 5.5 as the default daily driver.

💡 Why it matters to you: Fable 5.2 is now the default model in Claude Code (model ID claude-fable-5-2, 1M context) — worth testing on your Spring AI agent evals before paying for it everywhere.
Read deeper

Reported numbers for Fable 5.2 (vs. Fable 5.1 / Opus 5.5): FrontierCode 2.0 at Xhigh effort 49.1% (32.4% / 45.5%), FrontierSWE v2 69.9% (56.3% / 62.3%), OSWorld 2.1 89.3% (83.5% / 87.2%), Terminal-Bench-Science 74.6%, Humanity's Last Exam with tools 74.2%. Mythos 5.2 scores 76.3% on CyScenarioBench and 89.6% on CVE Rediscovery. These are Anthropic's own benchmark claims.

Pricing is $8 input / $40 output per million tokens at standard speed; fast mode (up to 2.5x faster generation) is $16/$80. It is available on AWS, Google Cloud and Microsoft Azure. Anthropic also says Fable 5.2 triggers about 55% fewer safeguard blocks than 5.1, and that over 90% of changes merged into its core codebase are now written by Claude.

Practical take for an application developer: the price is 4x+ a mid-tier model, so route only the hard planning/coding steps to Fable and keep summarisation/classification on Haiku 5.5 (see the Haiku story below).

Spring AI 2.1.0-RC2: DecisionModel API, tool-call argument streaming, “modern” MCP server

Spring Blog · Nov 9, 2026

The second release candidate for Spring AI 2.1 adds a DecisionModel API that returns typed yes/no, choice and score answers with probabilities, streaming of partial tool-call arguments (Anthropic, OpenAI, Bedrock Converse, DeepSeek) and support for the 2026-07-28 MCP revision via spring.ai.mcp.server.protocol=MODERN. It builds on Spring Boot 4.2.0-RC2.

💡 Why it matters to you: Directly your stack: DecisionModel gives you confidence-thresholded routing without parsing free text, and the Anthropic upgrade notes will bite if you pin temperature/topP.
Read deeper

Breaking changes to note: the Anthropic SDK 3.x defaults to API version 2026-10-21, which rejects temperature, topP and topK (Spring AI now drops them with a warning); API keys are sent as Authorization: Bearer; and prompt token counts now include cache reads/writes, so remove any manual adjustments or they'll be double-counted. Custom ChatModels that stream partial tool-call parts must also emit the complete ToolCallPart.

Other additions: DecisionDocumentReranker / DecisionDocumentFilter for decision-based RAG, DecisionToolIndex for picking the right tool (or reporting none applies), upsert() with precomputed embeddings for Neo4j, MongoDB Atlas, Typesense, MariaDB and Chroma, and a SessionService with optimistic concurrency (appendEvents with expectedVersion). Dependencies: MCP Java SDK 2.2.0-M2, Anthropic Java SDK 3.4.0. The team wants feedback on DecisionModel and the modern MCP server before GA.

DecisionResponse response = decisionModel.call(DecisionPrompt.builder()
    .text("My headphones arrived with the left side broken. Can I get a refund?")
    .question("defect", YesNoQuestion.builder()
        .text("Does the customer report a defect?")
        .whenYes("Part of the item does not work")
        .whenNo("The item works")
        .build())
    .build());

// Act only when the model is very confident
boolean defect = response.getYesNo("defect").isYes(0.9);

Spring AI 2.1 “Message Parts”: reasoning that survives the round trip

Spring Blog · Oct 28, 2026

Spring AI 2.1 stores model output as an ordered list of typed parts (text, reasoning, tool call, tool result, media, unknown) so reasoning blocks — Claude thinking blocks, Gemini thought signatures, OpenAI encrypted reasoning items — are replayed unchanged to the provider that produced them. Streaming and chat memory no longer drop reasoning.

💡 Why it matters to you: If your agents use extended thinking plus tools, multi-turn quality depends on replaying reasoning correctly — Spring AI now does it for you.
Read deeper

AbstractMessage now holds an ordered List<MessagePart>; MessagePart is a sealed interface with TextPart, ReasoningPart, ToolCallPart, ToolResultPart, MediaPart and UnknownPart. An OpaquePayload carries provider-specific data such as signatures; other providers skip it. getText(), getToolCalls() and getMedia() remain as views, and getReasoning() is new. There is also a new stateless OpenAiResponsesChatModel.

Spring AI Session stores full part lists in an append-only log and compacts only at turn boundaries; ChatMemory is deprecated and will be removed in 3.0.0. Caveats: Anthropic, Google GenAI and Bedrock now return one generation per candidate; histories saved before 2.1 have no reasoning parts; don't strip part attributes if you persist history yourself.

ChatResponse response = chatModel.call(prompt);

List<String> thoughts = response.getResult().getOutput()
    .getReasoning().stream()
    .map(ReasoningPart::text)
    .toList();

String answer = response.getResult().getOutput().getText();

Spring AI 2.1: bring your own embeddings — VectorStore.upsert() and vector queries

Spring Blog · Oct 28, 2026

Two new APIs let you manage vectors yourself: VectorStore.upsert(List<EmbeddedDocument>) stores vectors you supply, and similaritySearch(float[], SearchRequest) searches with a query vector. Use them for multimodal content (images, audio, video) or embeddings produced by batch APIs or migrations.

💡 Why it matters to you: You already use pgvector: this is how to build image-or-text product search in Spring Boot without forcing everything through a text embedding model.
Read deeper

The post's example indexes a furniture catalog with a multimodal model so “green velvet armchair” can match a product photo even when the description lacks those words. IDs derived from SKUs make re-indexing idempotent. Queries and indexed content must use a model built to compare those content types, and store dimensions must match the model output.

A single upsert isn't transactional — retry the whole list with the same IDs. As of 2.1.0-RC1 PGvector, Redis, Elasticsearch, Qdrant and OpenSearch support both features; others throw UnsupportedOperationException (RC2 adds Neo4j, MongoDB Atlas, Typesense, MariaDB and Chroma).

Document row = Document.builder()
    .id(UUID.nameUUIDFromBytes(sku.getBytes(UTF_8)).toString())
    .text("")
    .metadata(DocumentMetadata.CONTENT_REF.value(), photoUrl)
    .metadata("sku", sku)
    .build();

vectorStore.upsert(List.of(new EmbeddedDocument(row, vector)));

List<Document> results = vectorStore.similaritySearch(query,
    SearchRequest.builder().topK(12).filterExpression("inStock == true").build());

Trend: “decision models” (System One) arrive in every major AI stack at once

💡 Why it matters to you: Use cheap decision calls to gate expensive LLM calls — routing, reranking and “is a tool needed?” checks — and measure the saving.

Model Context Protocol (MCP)

MCP 2026-07-28 spec: stateless core, no init handshake — and Spring AI now speaks it

modelcontextprotocol.io / AAIF · Jul 28, 2026 (background; Spring AI support Nov 9)

The 2026-07-28 revision of the Model Context Protocol, described by the Agentic AI Foundation as the largest since launch, finalises a stateless design: the initialisation handshake is removed and protocol version and capabilities travel per request. Tasks move to an extension with poll-based tasks/get and tasks/update, and iss validation is mandatory.

💡 Why it matters to you: Stateless MCP servers scale like normal REST services — which is exactly what the new Spring AI “modern” MCP server targets.
Read deeper

All four Tier 1 SDKs speak the new revision and legacy versions get a 12-month window, per the MCP blog. Spring AI 2.1.0-RC2 enables it with spring.ai.mcp.server.protocol=MODERN (WebMVC, WebFlux and STDIO, sync only for now) and a request-state pattern for tools that ask the client for confirmation (elicitation).

This is four months old; I include it because this week's Spring AI and Claude Code releases (long-running MCP tasks go to the background; a fix for MCP OAuth requests leaking tokens on redirects) are the first time it shows up in the tools you use.

# application.properties (Spring AI 2.1.0-RC2)
spring.ai.mcp.server.protocol=MODERN

EvoMemState: evolving a memory state for personal LLM agents

arXiv 2611.03743 · Nov 2, 2026

A new paper proposes evolving a memory state for personal agents: a reinforcement-learning component generates a request-specific reasoning state over memory rather than just retrieving chunks. The authors report gains over existing memory systems on retrieval completeness and memory-grounded answer accuracy.

💡 Why it matters to you: Agent memory is the next RAG: the retrieve-then-stuff pattern is being replaced by learned, query-specific memory states — relevant to Spring AI Session Memory.
Read deeper

Simply put: instead of fetching the top-k similar notes, the system builds a state tailored to the current request and updates it over time. The gains are the authors' claims on their own benchmarks; I only read the abstract-level summary.
