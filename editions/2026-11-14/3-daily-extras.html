Codex Security (OpenAI): scan, validate and patch vulnerabilities from a CLI or TypeScript SDK

github.com/openai/codex-security · Trending Nov 14, 2026

A CLI (`cs`) and TypeScript SDK that scans a repo, paths or git diffs for vulnerabilities, validates candidate findings, generates patches and exports SARIF/JSON/CSV or a threat model. It also drafts SECURITY.md and runs in CI and GitHub Actions.

💡 Why it matters to you: Point it at one of your Spring Boot + React repos and make a “AI security review of my own project” video.
Read deeper

Requirements: Node.js 22.13+ (22.x), 24.x or 26.x, Python 3.10+, and an OpenAI sign-in or API key for CI. Scan modes include Standard and Deep (which repeats Standard scans and dedupes); providers include OpenAI, Amazon Bedrock, OpenRouter and Fireworks AI. Treat any AI-reported finding as a lead to verify.

npm install --global @openai/codex-security
cs login
cs scan . --diff origin/main        # review a PR-sized change
cs scan . --mode deep

Headroom: compress tool outputs, logs and RAG chunks before they hit the LLM

github.com/headroomlabs-ai/headroom · Trending Nov 14, 2026

A local compression layer (Python/TypeScript library, proxy and MCP server) that routes content by type — JSON, source code via AST, prose — and compresses it before the model sees it, with reversible retrieval of originals. The project claims ~20% fewer tokens for coding agents and 60–95% for JSON.

💡 Why it matters to you: Token cost is the real bill in agentic RAG; this is a drop-in way to test whether your tool outputs are bloated.
Read deeper

Project-reported measurements: code search 21%, SRE incident debugging 57%, codebase exploration 42%, GitHub issue triage 30%; 0.21 ms p50 overhead on a 10K-token JSON result; GSM8K unchanged at 0.870. These are the authors' benchmarks. An anonymous telemetry beacon is on by default (HEADROOM_OFFLINE=1 disables it).

pip install headroom-ai
headroom proxy --port 8787      # drop-in proxy
headroom wrap claude            # wrap a coding agent

NVIDIA SkillSpector: scan agent skills before you install them

github.com/NVIDIA/SkillSpector · Trending Nov 14, 2026

An open-source static scanner for AI agent skills (Claude Code, Codex, MCP) with 71 vulnerability patterns across 17 categories — prompt injection, data exfiltration, privilege escalation, supply-chain tricks, MCP tool poisoning. It scores 0–100: 0–20 SAFE, 21–50 CAUTION, 51+ DO NOT INSTALL.

💡 Why it matters to you: You install community Claude Code skills and plugins — run this first; and it's a perfect MCP-security tutorial topic.
Read deeper

It never executes the skill; with --no-llm nothing leaves your machine, otherwise scanned content goes to the configured LLM provider. It's static analysis, so it can't see runtime behaviour or compiled code. Exit codes make it CI-friendly (1 for scores above 50).

uv tool install git+https://github.com/NVIDIA/skillspector.git
skillspector scan ./my-skill/ --no-llm

⭐ GitHub repos of the day

volcengine/OpenViking — a filesystem-style context database for agents (42k★)

github.com/volcengine/OpenViking · Trending Nov 14, 2026

Stores an agent's knowledge, memories and skills in one virtual filesystem under viking://, browsed with ls/tree/read/grep and searched with scoped find. Directories carry generated L0/L1 summaries so full content loads only when needed.

💡 Why it matters to you: A fresh take on agent memory for the Spring AI / LangGraph agents you're building — and it ships a LangChain/LangGraph adapter.
Read deeper

Plugins cover Claude Code, Codex, Cursor and OpenCode; SDKs for Python, Go and TypeScript. Reported LoCoMo memory accuracy is 80–83% vs 24–57% on each agent's native memory — project-reported. Licence: AGPL-3.0 for the main project (some components Apache-2.0/MIT) — check this before using it in client products.

uv tool install openviking --upgrade && openviking-server init
ov add-resource https://github.com/volcengine/OpenViking
ov find "what is openviking"

alibaba/open-code-review — hybrid deterministic + LLM-agent code reviewer (Apache-2.0)

github.com/alibaba/open-code-review · Trending Nov 14, 2026

A Go CLI that reads git diffs, bundles files, matches rules (NPEs, thread safety, XSS, SQL injection) and lets an LLM agent search the codebase to produce line-level review comments. It has plugins for Claude Code, Codex and Cursor and CI support for GitHub Actions and GitLab CI.

💡 Why it matters to you: Java-flavoured rules like NPE and thread-safety suit Spring projects — and it's a reference design for an “AI PR reviewer” SaaS.
Read deeper

The README's benchmark (AACR-Bench: 50 repos, 200 PRs) reports higher precision and F1 than Claude Code on the same model at about one-ninth of the tokens, with lower recall — the project's own result. Requires Git 2.41+.

npm install -g @alibaba-group/open-code-review
ocr config provider && ocr config model
ocr review --from main --to feature-branch

ChromeDevTools/chrome-devtools-mcp — DevTools for coding agents

github.com/ChromeDevTools/chrome-devtools-mcp · Trending Nov 14, 2026

An MCP server (also a CLI) that lets Claude, Cursor or Copilot drive a live Chrome: record performance traces, inspect network requests, take screenshots, read source-mapped console errors and automate actions through Puppeteer.

💡 Why it matters to you: Lets your agent debug the React front end of your full-stack app, not just edit it.
Read deeper

The browser starts only when a tool needs it. Requires Node LTS and current stable Chrome; flags include --headless, --isolated and --slim. Usage statistics and update checks can be disabled by flag or env var.

{
  "mcpServers": {
    "chrome-devtools": {
      "command": "npx",
      "args": ["-y", "chrome-devtools-mcp@latest"]
    }
  }
}

💡 Project ideas of the day

AI support-ticket triage with Spring AI DecisionModel (Spring Boot + React)

Inspired by Spring AI 2.1.0-RC2 · Idea — original suggestion

Build a helpdesk app where each incoming ticket is classified with typed yes/no/score questions (“is this a defect?”, “is the customer angry?”) and routed only when confidence passes a threshold; low-confidence tickets go to a human queue. React dashboard shows confidence and overrides.

💡 Why it matters to you: A tutorial that teaches the newest Spring AI API, gives a SaaS-shaped demo and ends in a portfolio piece.
Read deeper

Stack: Spring Boot 4.x, Spring AI 2.1 (DecisionModel with Ollama's small default model so students need no API key), Postgres, React + Vite. Teach threshold tuning with a small labelled CSV and a confusion matrix. Note: DecisionModel is in a release candidate, so pin versions in the course repo.

Image-and-text product search using your own embeddings (pgvector)

Inspired by Spring AI 2.1 own-embeddings post · Idea — original suggestion

Index a small catalog of product photos with a multimodal embedding model, store vectors via VectorStore.upsert(), and let shoppers search with text or by uploading a photo. Filter on stock and price with metadata expressions.

💡 Why it matters to you: Uses a real new feature, looks impressive on video, and maps to Indian D2C stores (fashion, home décor).
Read deeper

Stack: Spring Boot, Spring AI PGVector store, a multimodal embedding model, React with a drag-and-drop upload. Use SKU-derived UUIDs so re-indexing is idempotent. Make the point that query and catalog must use the same multimodal model.

  • Spring AI own-embeddings post

“Is this skill safe?” — an MCP/skill security scanner web app

Inspired by NVIDIA SkillSpector and MCP security research · Idea — original suggestion

A web app where developers paste a GitHub URL of an MCP server or Claude Code skill and get a risk report: static checks (like SkillSpector's) plus an LLM explanation in plain English and a suggested least-privilege config.

💡 Why it matters to you: Security + AI is a hiring-friendly niche, and it makes a clean three-part series: scanner core, API, React UI.
Read deeper

Start by wrapping an existing open-source scanner via CLI from a Spring Boot service, queue scans in Redis or Kafka, and show SARIF results in React. Add rate limits and sandboxed cloning — you'd be fetching untrusted code, so never execute it.

📚 Learn this today

Learn today: validate and self-correct structured LLM output in Spring AI

Spring AI 2.0 GA notes · 20–30 minute exercise

Spring AI 2.0 added a StructuredOutputValidationAdvisor that can make the model self-correct when its output fails validation. Today: build a ChatClient endpoint that returns a Java record and handle invalid output.

💡 Why it matters to you: Structured output that fails validation is the most common production bug in LLM apps — fix it once and your RAG and agent code gets sturdier.
Read deeper

Plan: (1) define a record with Bean Validation constraints; (2) call ChatClient with entity(MyRecord.class); (3) deliberately prompt for a bad value and watch it fail; (4) add the validation advisor from the Spring AI 2.0 docs and compare retries and cost; (5) log token use per request. I haven't verified the advisor's exact configuration API — check the 2.0 reference docs.

Stretch goal: use Spring AI 2.1's DecisionModel to decide whether to retry at all.

record Ticket(@NotBlank String category, @Min(1) @Max(5) int priority) {}

Ticket t = chatClient.prompt()
    .user("Classify: my invoice is wrong and I'm furious")
    .call()
    .entity(Ticket.class);
