AI tools of the day

Tool: LiteLLM 1.111.0, one gateway that now lists claude-fable-5-2

LiteLLM GitHub release v1.111.0 · Nov 25, 2026

LiteLLM 1.111.0 adds claude-fable-5-2 and its Claude Platform on AWS mirror, plus Azure AI and Vertex AI rows. It is a breaking release for audio: transcriptions are now billed by the seconds the provider reports. It also adds OpenSearch index pass-through with per-key read and write grants.

💡 Why it matters to you: One OpenAI-compatible endpoint in front of Claude, Gemini and Ollama lets your Spring AI app switch models by changing a URL, and it gives you spend tracking.
Read deeper

Two backport releases (1.109.5 and 1.110.4) the same day update the standalone UI image to nginx 1.31.10 and zlib 1.4 and make end-user restriction refreshes read only restricted customers. They need no action to upgrade.

Point Spring AI's OpenAI client at the proxy base URL to try it; check the LiteLLM docs for the exact model name mapping.

spring.ai.openai.base-url=http://localhost:4000
spring.ai.openai.api-key=sk-litellm-key
spring.ai.openai.chat.options.model=claude-fable-5-2

Tool: CrewAI 1.15.45 saves versioned artifacts and tightens server authentication

CrewAI GitHub releases · Nov 19 to 24, 2026

CrewAI 1.15.44 (Nov 19) saves files as versioned, shareable artifacts and limits Pillow to PNG, JPEG, GIF and WEBP. 1.15.45 (Nov 24) saves HTML or Markdown output as a PDF artifact, rejects empty credentials, uses constant-time comparison in server authentication and drops credentials on cross-origin redirects.

💡 Why it matters to you: It is a Python multi-agent option to compare with LangGraph, and the PDF artifact output is handy for a demo that produces a report.
Read deeper

1.15.43 fixed multimodal detection for Claude 5. The security items are the interesting part: constant-time comparison and credential dropping on redirects are exactly the classes of bug the MCP and Spring Security advisories keep hitting.

pip install -U crewai==1.15.45

Tool: MCP Inspector, test any MCP server from the browser before wiring a client

modelcontextprotocol/servers README · repo page read Nov 25, 2026

The reference servers repo documents the MCP Inspector for testing a server without configuring a client. You run it with npx and point it at your server command, for example the Git server through uvx.

💡 Why it matters to you: Before you plug a home-grown Spring AI MCP server into Claude Code or Cursor, check its tools, schemas and errors in the Inspector.
Read deeper

By default a server uses stdio: it opens no port and waits for messages, so it can look as if it hangs when run directly. Add --transport streamable-http to serve at http://127.0.0.1:3001/mcp.

The README notes that the reference servers are educational examples and not production-ready, so apply the same caution to community servers.

npx @modelcontextprotocol/inspector uvx mcp-server-git

Repo: langchain-ai/langgraph, a durable, stateful agent framework (about 45.4k stars)

GitHub repository page · read Nov 25, 2026

LangGraph describes itself as a low-level orchestration framework for long-running, stateful agents. It offers durable execution, human-in-the-loop state inspection, short and long-term memory and LangSmith debugging. The repo has about 45.4k stars, 7.9k forks and an MIT licence.

💡 Why it matters to you: Spring AI Agent, announced for December, covers similar ground, so learning LangGraph's state-graph model now will carry over.
Read deeper

It is built by LangChain but works without LangChain. Install with pip install -U langgraph, then follow the quickstart in the docs, because the repo page itself has no code sample. The latest release is 1.2.24 (covered in the AI Engineer paper).

Repo: pgvector/pgvector, vector search inside Postgres (about 23.8k stars, now with a pg19 image)

GitHub repository page · read Nov 25, 2026

pgvector is open-source vector similarity search for Postgres with exact and approximate search, half, binary and sparse vectors, and six distance metrics. It offers HNSW and IVFFlat indexes and keeps Postgres ACID, point-in-time recovery and JOINs. The repo has about 23.8k stars and lists a pgvector/pgvector:pg19-trixie image.

💡 Why it matters to you: It is the vector store behind most Spring AI RAG tutorials, so one Postgres does your relational data and your embeddings.
Read deeper

HNSW gives a better speed-recall tradeoff but builds slower and uses more memory; IVFFlat builds faster and uses less memory but queries more slowly. For parallel HNSW builds in Docker, pass --shm-size=1g.

Spring AI 2.0.3 also fixed PgVectorStore so it skips vector size validation when dimensions are unset.

CREATE EXTENSION vector;
CREATE TABLE items (id bigserial PRIMARY KEY, embedding vector(3));
INSERT INTO items (embedding) VALUES ('[1,2,3]'), ('[4,5,6]');
SELECT * FROM items ORDER BY embedding <-> '[3,1,2]' LIMIT 5;

Project ideas of the day

Idea: a cost-aware model router for Spring AI, with a React spend dashboard

Inspired by Gemini 4 Hydrogen and the LiteLLM 1.111.0 gateway

Build a Spring Boot service that sends cheap steps (classification, summarising, tool routing) to a fast model such as Gemini 4 Hydrogen and hard planning steps to a bigger one, logs tokens and cost per request, and shows spend per route in a React dashboard.

💡 Why it matters to you: It teaches multi-model design, a skill you will need as model names and prices change every few weeks, and it makes a strong video on cutting LLM cost.
Read deeper

Keep model names in configuration, route by an explicit task type, and record input and output tokens from each response. Compare a run with everything on the big model against the routed run on the same 50 test prompts and publish both costs and quality scores.

Optional: put LiteLLM in front so Spring AI only sees one OpenAI-compatible base URL, and read spend from its logs.

  • Original: Gemini 4 Hydrogen
  • Related: LiteLLM releases

Idea: a memory-evaluation harness that scores retrieval evidence and answers separately

Inspired by the arXiv memory-evaluation papers in today's AI Engineer paper

Build a small evaluator that runs your agent's memory (plain RAG over chat history versus a fancy summariser) on test conversations, logs the chunks retrieved and scores retrieval and answer separately, with a random-retrieval control.

💡 Why it matters to you: It would give you data for a video on whether complex memory is worth it, and it is a reusable tool for every RAG project.
Read deeper

Start with a verbatim baseline over pgvector, then add one smarter method. Report three numbers per method: retrieval hit rate, answer correctness, and answer correctness with random chunks. If the random control scores well, your benchmark is too easy.

The idea follows the recommendations in the MemDelta and naive-RAG papers; read them first.

  • Original: arXiv 2610.30755
  • Related: arXiv 2606.29914

Idea: an AI nightly job runner on Spring Batch 6.1 that enriches records with a DecisionModel

Inspired by Spring Batch 6.1 and the Spring AI 2.1 DecisionModel API

Build a Spring Batch job that reads rows (support tickets or product reviews), asks a Spring AI DecisionModel for a typed label with a probability, and writes results back, with low-confidence rows routed to a manual-review queue.

💡 Why it matters to you: Spring Batch 6.1 makes restarts cheap and parameters clean, and Decision Models give typed answers, a good fit for a tutorial on production AI pipelines.
Read deeper

Use @JobParameter for the input file, a PageableItemReader for database input, and chunk-level retries for model errors. Add per-turn call limits so a bad prompt cannot run away; Spring AI 2.1 defaults are 40 per tool and 150 per turn.

Measure cost per thousand rows and publish it; that number makes the video useful.

  • Original: Spring Batch 6.1
  • Related: Spring AI 2.1.0 GA

Learn this today

Learn today: run MCP Inspector against two reference servers and compare stdio with Streamable HTTP

About 30 minutes · needs Node and uv installed

In 30 minutes, start the Git server with uvx and the Memory server with npx, open each in the MCP Inspector, call a tool, then restart one with --transport streamable-http and compare how the connection works. You will learn what a tool schema, a transport and a session look like on the wire.

💡 Why it matters to you: Every Spring AI MCP server you build next, and every security advisory about MCP, will make more sense once you have seen the raw tool list and the stdio versus HTTP difference.
Read deeper

Steps: 1) run the inspector command with uvx mcp-server-git, 2) list the tools and call one, 3) repeat with npx -y @modelcontextprotocol/server-memory, 4) start a server with --transport streamable-http and open http://127.0.0.1:3001/mcp from the inspector. Then ask: what does a stdio server run on my machine, and what can it touch?

Bonus: read about the MCP 2026-07-28 stateless revision and note which parts of your session would no longer be stored on the server.

npx @modelcontextprotocol/inspector uvx mcp-server-git
npx @modelcontextprotocol/inspector npx -y @modelcontextprotocol/server-memory
