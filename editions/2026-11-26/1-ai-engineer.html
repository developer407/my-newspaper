Claude Platform release notes · Nov 23, 2026

Anthropic's release notes schedule two removals for Nov 30, 2026: Claude Sonnet 4.5 (claude-sonnet-4-5-20250929) is retired on the Claude API, and fast mode for Opus 4.8 is removed. The suggested migration targets are Sonnet 5.5 and Opus 5.5. Opus 4.5 follows on Jan 22, 2027.

💡 Why it matters to you: Any Spring AI or LangChain4j app with a pinned model id in application.yml will start returning errors after Nov 30 if it still names Sonnet 4.5.
Read deeper

Moving to Sonnet 5.5 is not a pure rename. The release notes warn that Sonnet 5 code can break in five ways, including forced tool_choice returning a 400, and that Haiku 5.5 uses a new tokenizer that produces more tokens, so cost and context math change.

Claude API adds message threads, linked billing and self-hosted Managed Agents (all beta)

Claude Platform release notes · Nov 2 to Nov 12, 2026

In November the Claude API gained message threads (Nov 2), which keep conversation state on the server so later requests send only new messages, and threads expire 5 minutes after the last request. Linked billing (Nov 17) lets customers pay for usage in your app through their own organization via a billing_policy field. Self-hosted Claude Managed Agents (Nov 12) lets you run the full service on your own infrastructure, by contacting the account team.

💡 Why it matters to you: Server-side threads and per-customer billing are exactly the plumbing a multi-tenant RAG or chat backend would otherwise build by hand on top of Spring AI chat memory.
Read deeper

Message threads change the usual stateless chat loop: instead of replaying the whole history from your ChatMemory each turn, you hold a thread and send deltas. The 5-minute expiry means it is a cache-like convenience, not durable storage, so keep your own transcript if you need it.

Linked billing uses the user-profiles-billing-2026-10-01 beta header and a billing_policy parameter on /v1/messages and /v1/chat/completions. All of these are beta, so expect shape changes before you build a product on them.

Fable 5.2 migration checklist: four 400-error traps in the new Claude models

Claude Platform release notes · Nov 9, 2026

The Fable 5.2 and Mythos 5.2 launch notes list breaking changes: the prefix check is enforced for all accounts, so editing system, tools or earlier messages before replaying a thinking block returns a 400. The computer_20251124 tool returns a 400 except on Bedrock (use computer_toolset_20260801), and the advisor tool must itself be Fable 5.2 or Mythos 5.2. Thinking blocks are dropped when a conversation moves to a model outside the pair.

💡 Why it matters to you: Agent loops built on Spring AI or LangGraph that edit history between turns or swap models mid-conversation are the likeliest to hit these errors.
Read deeper

The prefix rule matters for context-management tricks such as trimming tool results or rewriting the system prompt between turns. If you do that with thinking enabled, replay the thinking blocks against an unchanged prefix or drop them entirely.

Both models also require 30-day data retention and are not available under zero data retention unless Anthropic authorizes it, which matters for regulated Indian BFSI clients. Pricing is $8 input and $40 output per million tokens, with a fast mode at $16 and $80.

Anthropic Java SDK 3.11 to 3.14: Bedrock base URL, a completion executor and Opus 4.5 deprecation

GitHub releases, anthropics/anthropic-sdk-java · Nov 19-24, 2026

Four releases in six days. v3.13.0 adds a Bedrock custom base URL (BedrockBackend.builder().baseUrl(...) or ANTHROPIC_BEDROCK_BASE_URL), Admin API external storage with webhooks, and marks Claude Opus 4.5 deprecated with end-of-life on Jan 22, 2027. v3.12.0 adds a completionExecutor option: async requests and callbacks run on a dedicated pool of up to 64 threads, falling back to the submitting thread when all are busy. v3.14.0 adds compliance review case support.

💡 Why it matters to you: Spring AI 2.1 depends on this SDK for its Anthropic module, and the executor change affects anyone running async calls inside a Spring Boot request thread.
Read deeper

The completionExecutor note is a gotcha: if your callbacks block (for example on JDBC), pass your own executor or the 64-thread pool can saturate, and work then runs on the submitting thread. An async call still in flight when the client closes fails with RejectedExecutionException.

The Bedrock base URL option is useful for VPC endpoints, which is common in Indian enterprise AWS setups. Requests are still signed for the configured region.

BedrockBackend backend = BedrockBackend.builder()
    .baseUrl("https://your-vpc-endpoint...")
    .build();

MCP and protocols

MCP draft file upload and download extension: move files without pushing them through the model context

MCP blog · Nov 10, 2026

The File Uploads Working Group published a draft experimental extension, io.modelcontextprotocol/files. A server marks file arguments with x-mcp-file in its tool schema; the client sends only metadata first, the server checks permissions and quota, then returns an upload_required result with an upload URL and a requestState value so the client can upload over HTTPS and retry the tool call. Downloads work in reverse through _meta.

💡 Why it matters to you: Any Spring-based MCP server that needs to accept a PDF or CSV for a RAG pipeline will eventually use this instead of base64 blobs in tool arguments.
Read deeper

Each upload or download target has a credentials setting (omit or include) controlling whether MCP credentials are sent, and the draft recommends hosts allowlist omit origins, which limits token leakage to storage services.

It is optional, has no reference implementation yet and is expected to stabilize by the end of 2026. The authors want feedback through the repo, issues or the working group Discord.

MCP moves to a six-month release cycle: next spec is 2027-03-30

MCP blog · Nov 11, 2026

MCP will publish spec revisions on a regular six-month cadence, generally the last Tuesday of March and September. The next release is targeted for March 30, 2027 under the identifier 2027-03-30, and proposals that are not ready move to a later release instead of delaying the whole spec. Luca Chang joins as a Release Manager.

💡 Why it matters to you: A predictable cadence lets you plan Spring AI and MCP SDK upgrades instead of chasing surprise revisions.
Read deeper

The timeline: planning begins eight months before release, soft freeze 2.5 months out, Tier 1 SDK betas 1.5 months out, and hard freeze one month out with only critical security or correctness fixes allowed. The process is documented in SEP-3398.

The post states this changes how releases are prepared, not the protocol, so existing clients and servers need no changes.
