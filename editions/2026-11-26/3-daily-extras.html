AI tools of the day

Replit Missions: hand an agent swarm a goal and a hard budget cap

Replit / The New Stack · Nov 17, 2026 (search-sourced)

Replit Missions lets you agree four terms up front (approach, success criteria, boundaries and a maximum AI spend) and then runs a swarm of agents toward the goal. Replit checks spend at every step and blocks paid services once the budget is hit, though work already in flight can overshoot slightly. A separate agent judges results against your success criteria.

💡 Why it matters to you: The budget-first, judge-agent design is a pattern you can copy in a Spring AI orchestrator and teach in a tutorial.
Read deeper

Replit's own demo says a swarm built a monitoring platform called DataCat in two days within a $3,000 budget, and its NumPy benchmark showed diminishing returns: 4x for one agent, 17x for 16 agents, 19x for 32. These numbers come from Replit's own tests and are not independently verified.

One outlet contrasts the pricing model with Devin (per task) and Claude Code (per token): Missions sells a budget-capped outcome rather than a seat. I could not fetch the Replit blog itself, so details are from search results.

Claude Meetings (beta): Claude joins your Google Meet call as a participant

Anthropic, via IT Brief and others · Nov 10, 2026 (search-sourced, older than 14 days)

Claude Meetings joins a video call as a visible participant, takes notes, answers questions in the call chat, pulls data from connected apps and drafts project plans and timelines. It is in beta on paid Team and Enterprise plans, Google Meet only at launch. Claude Whiteboards and Claude Sheets were announced alongside it.

💡 Why it matters to you: It is a ready-made reference for the meeting-agent product category, useful before you build your own with Spring AI tools and MCP connectors.

Repo: firecrawl/firecrawl, web scraping and search API for agents (about 210k stars)

GitHub · Nov 26, 2026

Firecrawl turns websites into clean markdown or structured JSON and offers scrape, crawl, map, batch scrape and search from one API, plus PDF and Office parsing and an autonomous agent mode. It has about 210.1k stars and 11k forks, and is trending today. The main project is AGPL-3.0; SDKs and some UI parts are MIT.

💡 Why it matters to you: It is a quick way to feed a RAG pipeline in Spring AI or LangGraph, and it has an official Java SDK.
Read deeper

Official SDKs cover Python, Node.js, Go, Java, Rust, Ruby, .NET, PHP and Elixir. An MCP server registers with Claude Code, Cursor and Codex via firecrawl-local init. Note the AGPL license if you self-host a modified server inside a product.

npx -y firecrawl-cli@latest scrape https://firecrawl.dev
# or: pip install firecrawl

GitHub · Nov 26, 2026

It is self-hosted, works with your own models, and has 60+ integrations including GitHub, Jenkins, Grafana, Datadog, Kubernetes and PagerDuty. About 15.5k stars, Apache 2.0, public alpha.

💡 Why it matters to you: A real-world agent with tools and approvals to study before building a Spring AI CI-triage bot.

Idea: a budget-capped agent runner for Spring AI, with a React cost-per-step view

Inspired by Replit Missions · Nov 17, 2026 (search-sourced)

Replit Missions makes you set a spend limit before an agent run and checks it at every step. Build the same contract for Spring AI: a mission with goal, success criteria and max tokens or rupees, enforced by an advisor.

💡 Why it matters to you: It combines Spring AI advisors, session state and a React dashboard in one teachable app.
Read deeper

Stack: Spring Boot, Spring AI ChatClient with a custom advisor that reads token usage from each response and aborts at the cap, Postgres for mission and step rows, React with a live cost chart over SSE.

Build steps: 1) Mission entity with budget and status. 2) Advisor that sums usage per step and throws BudgetExceeded. 3) A judge call that scores the final output against the criteria. 4) SSE endpoint streaming steps. 5) React page with budget burn-down. Note Replit's docs admit in-flight work can overshoot, so show that in your design.

Inspired by Tracer-Cloud/opensre · GitHub, Nov 26, 2026

OpenSRE shows demand for agents that read failed CI runs and propose fixes. A Spring AI version is a good tutorial: receive a GitHub webhook, fetch logs, classify the failure and comment on the PR.

💡 Why it matters to you: It uses tool calling, structured output and GitHub integration, with a clear human-approval step.
Read deeper

Stack: Spring Boot webhook endpoint, Spring AI tool calling for log fetch and file read, structured output for a classification record (infra, flaky test, code bug), GitHub REST for comments, optional React review queue.

Build steps: 1) Verify webhook signature. 2) Download job logs. 3) Trim logs to the failing step. 4) Ask the model for category, cause and suggested patch. 5) Post a comment; never push without approval. 6) Evaluate on 20 saved failures.

Learn today: scrape a docs site into clean markdown with Firecrawl and chunk it for RAG

Firecrawl README · Nov 26, 2026

RAG quality starts with clean input. Firecrawl returns markdown instead of raw HTML, so chunking by headings becomes trivial. Exercise: scrape one documentation page, split by headings and look at the chunks.

💡 Why it matters to you: It is the ingestion step missing from most Spring AI RAG tutorials, and you can feed the chunks to a VectorStore afterwards.
Read deeper

Steps: 1) Run the CLI command below on a Spring AI docs page. 2) Save the markdown. 3) Split on lines starting with ## so each chunk is one section. 4) Print chunk sizes and drop anything under 200 characters. 5) Stretch goal: embed chunks into pgvector and ask three questions.

Check the robots rules and licence of any site before ingesting it, and keep the source URL as metadata for citations.

npx -y firecrawl-cli@latest scrape https://docs.spring.io/spring-ai/reference/ > page.md

# split by H2 (Java 21)
var chunks = java.nio.file.Files.readString(java.nio.file.Path.of("page.md")).split("(?m)^(?=## )");
for (var c : chunks) if (c.length() > 200) System.out.println(c.length() + " | " + c.lines().findFirst().get());
