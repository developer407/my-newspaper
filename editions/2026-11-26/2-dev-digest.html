Java and Spring

Spring Boot 4.2.0 is GA: Framework 7.1, Security 7.2 and Batch 6.1 in one train

Spring Boot GitHub release · Nov 19, 2026

Spring Boot 4.2.0 shipped on Nov 19 with a refined forwarded-header support and a deprecation of Apache Pulsar auto-configuration. The BOM pulls in Spring Framework 7.1.0, Spring Security 7.2.0, Spring Batch 6.1.0, Spring Data 2026.1.0, Spring GraphQL 2.1.0, Spring Kafka 4.2.0 and Hibernate 7.4.15. Micrometer is 1.18.0 and OpenTelemetry is 1.68.0.

💡 Why it matters to you: If your Spring AI 2.1 services sit on Boot 4.1, this is the coordinated upgrade target that the newest Spring AI extensions (sessions, Boot 4.2 utilities) already assume.
Read deeper

The headline feature list is short because most of the 4.2 work landed in the milestones and RC builds. The GA release itself adds the forwarded header refinement (reactive servers no longer apply forwarded headers when running on a cloud platform) and fixes for a concurrent class loading 'Zip file closed' error, RabbitMQ and AMQP percent-encoded URIs, Docker Compose JDBC URLs for PostgreSQL database names, and SAML2 metadata when the single logout binding is omitted.

Upgrade note: Apache Pulsar support is deprecated in 4.2. 4.1.3 and 4.0.10 shipped the same day as maintenance releases if you are not ready to move. Run spring-boot-properties-migrator while you upgrade, although the release notes mention it missed some properties renamed in 4.0.

Spring Framework 7.1.0: stricter data binding, SpEL depth cap of 200, JPA 4.0 groundwork

Spring Framework GitHub release · Nov 19, 2026

Spring Framework 7.1.0 went GA on Nov 19 with consistent reporting of invalid list and array indexes in property paths, constructor binding that always throws BeanInstantiationException, and a lower default maximum SpEL nesting depth of 200. It upgrades Micrometer to 1.18.0 and Reactor to 2026.0.0. A 7.0.11 maintenance release landed alongside it.

💡 Why it matters to you: Binding and SpEL limits change error behaviour in your REST controllers and any dynamic expressions, and 7.1 is the base for Boot 4.2.
Read deeper

From the RC1 notes (Oct 22): APIs deprecated for removal in 7.1 are gone, 0 now means 'no timeout' across several clients, and WebFlux multipart defaults were aligned with Spring Boot and Tomcat. New items in the 7.1 line include JsonUnit as a JSON comparison option in test APIs, problem details rendering, JPA 4.0 package discovery and a batch DSL for JdbcClient.

7.0.11 adds pause and restart callbacks to SmartLifecycle and fixes @Retryable and @ConcurrencyLimit on JDK dynamic proxies. Check the 'full release notes' linked from the release page for the complete breaking-changes list before you upgrade.

MongoDB Node driver 7.9.1 and 7.9.0: OIDC token leak and NUL-byte PLAIN auth fixes

node-mongodb-native GitHub releases · Nov 19, 2026

Driver 7.9.1 (Nov 19) rejects credentials containing NUL characters for PLAIN authentication, which could change the identity the server authenticated, and redacts connection-string values from error messages and logs (CVE-2026-129929, CVE-2026-129930). Driver 7.9.0 (Nov 12) fixed OIDC bearer tokens being sent to domains the app had not allowlisted (CVE-2026-126835). A 6.22.0 patch (Nov 3) deprecates the experimental timeoutMS after a pool desynchronization issue that could expose other users' data (CVE-2026-119179).

💡 Why it matters to you: Every MERN app on Mongoose pulls this driver; Mongoose 9.13.0 already bundles driver 7.9, so check your lockfile.
Read deeper

timeoutMS and timeoutMode are now deprecated and have no effect in 6.22.0. Use serverSelectionTimeoutMS, waitQueueTimeoutMS, socketTimeoutMS and maxTimeMS instead.

7.9.0 also makes dropIndexes swallow only NamespaceNotFound errors, and the driver respects Node's process-level autoSelectFamily default.

Mongoose sanitizeFilter was not applied to countDocuments: CVE-2026-125120, CVSS 9.8

GitHub Advisory Database · Nov 10, 2026

Mongoose's sanitizeFilter, which guards against query selector injection, was not applied to countDocuments() queries, leaving that path open to NoSQL operator injection. Fixed in 6.13.11, 7.8.12, 8.24.3 and 9.9.2. The advisory is rated Critical at CVSS 9.8, weakness CWE-943.

💡 Why it matters to you: A MERN API that passes req.query or req.body straight into countDocuments for pagination totals is the classic exposure.
Read deeper

Affected: below 6.13.11, 7.0.0 to below 7.8.12, 8.0.0 to below 8.24.3, and 9.0.0 to below 9.9.2. Mongoose 9.13.x, released this week, is past the fix.

Workaround if you cannot upgrade: a plugin that calls mongoose.sanitizeFilter(this.getFilter()) in a pre('countDocuments') hook. Also validate and cast input at the route layer, since sanitizeFilter is only one layer.

schema.pre('countDocuments', function () {
  mongoose.sanitizeFilter(this.getFilter());
});

MCP Python SDK OAuth client could send credentials to a server-chosen authorization server (CVE-2026-115563)

GitHub Advisory Database · Nov 19, 2026

The mcp Python SDK's OAuth client let a connected MCP server decide where the client's credentials went, because authorization server metadata issuer was not validated on every path and stored client credentials were not bound to their server. Exposed material could include client_secret, authorization codes, PKCE code_verifier and signed client assertions. Fixed in 2.2.0 and 1.30.0; rated High (CVSS 7.5).

💡 Why it matters to you: Any Python MCP client you build for an agent that connects to third-party MCP servers over OAuth is in scope; Spring AI MCP clients are not covered by this advisory.
Read deeper

Not affected: servers built with the SDK, stdio clients, and clients that attach their own tokens or headers. For ClientCredentialsOAuthProvider and PrivateKeyJWTOAuthProvider, also pass issuer= (omitting it warns now and becomes an error in 3.0). Clear stored OAuth client registrations so the client re-registers.

If a client may have connected to an untrusted MCP server, rotate its client secret and revoke tokens. Red Hat's tracker also lists a similar flaw for other MCP SDKs (CVE-2026-104850) and a TypeScript SDK audience check gap (CVE-2026-111771), seen via search only.

pip install -U "mcp>=1.30.0"

Gradle fails open on repository errors: CVE-2026-22865, fixed in 8.14.4 and 9.3.0

GitHub Advisory Database · Nov 23, 2026

Gradle searches repositories in declaration order, and in older versions some connection exceptions such as NoHttpResponseException were not treated as fatal, so after retries it moved to the next repository. An attacker who can disrupt an earlier repository and controls a later one could serve malicious artifacts. Rated High, CVSS v4 8.6; a sibling advisory CVE-2026-22816 describes a similar failure.

💡 Why it matters to you: Java teams on Gradle (or following the supply chain theme from the npm worms) should turn on dependency verification and repository content filtering.
Read deeper

Affected: below 8.14.4 and 9.0.0 up to but not including 9.3.0. The CVE was published in January; the GitHub advisory database entry shows Nov 23.

Recommended mitigations if you cannot upgrade: dependency verification, strict repository content filtering, and removal of unused repository declarations.

./gradlew --write-verification-metadata sha256 help

ruflo MCP bridge: unauthenticated RCE in default Docker Compose, CVSS 10 (CVE-2026-59726)

GitHub Advisory Database · Nov 24, 2026 (added; first published July 2026)

The npm package ruflo, an AI agent orchestration project, exposed POST /mcp without authentication in its default Docker Compose setup, binding both the bridge and MongoDB to all interfaces. An unauthenticated attacker could run the terminal_execute tool, get a shell as the node user, and read provider API keys from the container environment. Fixed in 3.16.3; CVSS 10.0.

💡 Why it matters to you: It is a textbook case for your own MCP server work: bind to loopback, require a bearer token, and gate shell-like tools.
Read deeper

The fix binds to loopback by default, adds bearer token auth, gates terminal_execute behind an opt-in, enables MongoDB authentication, uses a read-only container and adds a CORS allowlist.

Operator actions: firewall ports 3001 and 27017, rotate OpenAI, Google, OpenRouter and Anthropic keys, and audit the AgentDB pattern store for injected entries, since redeploying does not remove poisoning. This advisory entered the GitHub database this week but the underlying report dates from July.

Databases and DevOps

pgJDBC 42.7.15 is a security release: SQL parsing hardening and stricter ssl values

GitHub releases (pgjdbc) · Nov 23, 2026

pgjdbc 42.7.15 fixes multiple security vulnerabilities (seven GHSA advisories are listed). It hardens SQL parsing of quoted text, dollar quotes, E'' strings and {fn} escapes, closes the connection after unchecked exceptions, rejects unrecognized ssl values that used to fall back to prefer, and qualifies catalog queries with pg_catalog. The previous 42.7.14 (Oct 7) fixed a requireAuth bypass (CVE-2026-107314) and a padding data leak (CVE-2026-107315).

💡 Why it matters to you: Spring Boot's default PostgreSQL driver is pgjdbc, so every Postgres-backed service you run should pick this up, and any config with a typo'd ssl value will now fail instead of silently using prefer.
Read deeper

The behavior changes can break startup: an unrecognized ssl value is now rejected, and 42.7.14 made connections fail if requireAuth excludes every method. Use a positive list such as requireAuth=scram-sha-256.

Spring Boot's dependency management may lag the driver; override the postgresql version property if you need the fix before the next Boot patch.

<properties>
  <postgresql.version>42.7.15</postgresql.version>
</properties>
# JDBC URL
jdbc:postgresql://db:5432/app?sslmode=verify-full&requireAuth=scram-sha-256

GitHub releases (Redux Toolkit) · Nov 18, 2026

RTK 2.15.0 gives each store its own RTK Query runtime state so SSR and tests sharing one api no longer interfere. initiate() promises now resolve with their own request's result, queries get a startReason, and pollingInterval can be a function of the cache entry.
