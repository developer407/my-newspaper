Tool: opencode 2.3.2, an open-source coding agent that fixed a costly prompt-caching bug

sst/opencode release v2.3.2 · Nov 18, 2026

opencode 2.3.2 fixes GPT-6.2 models re-billing the system prompt as uncached input on every step. The notes say uncached input per step on GitHub Copilot's gpt-6.2-sol dropped from about 14,000 tokens to 3. Version 2.3.1 moves long-running shell commands to the background and writes compaction summaries in the background.

💡 Why it matters to you: It is a terminal coding agent you can point at your own Spring Boot repo, and the caching story is a good lesson in why agents get expensive.

GitHub repos of the day

Repo: Atmosphere/atmosphere, a portable AI agent runtime for the JVM (about 3.8k stars)

github.com/Atmosphere/atmosphere · pushed this week

Atmosphere lets one @Agent class run on Spring AI, LangChain4j, Anthropic or other frameworks behind a single SPI. It streams tokens over WebSocket, SSE, long-polling or gRPC, supports tool calls (@AiTool), human approval gates and durable workflows, and exposes the agent over MCP, A2A and AG-UI.

💡 Why it matters to you: It targets exactly your stack: a Spring Boot starter on the back end and atmosphere.js clients for React.
Read deeper

Governance features include policy admission, @AgentScope topic limits, cost ceilings, PII redaction and admin kill switches. Requirements per the README: Java 21+, Spring Boot 4.1.1 (or Boot 3.5 with a profile) and Quarkus 3.39.5+. The README showed no tagged GitHub release, so check Maven Central for the version.

Treat it as early-stage and read the license and code before using it in production.

<dependency>
  <groupId>org.atmosphere</groupId>
  <artifactId>atmosphere-spring-boot-starter</artifactId>
  <version>${atmosphere.version}</version>
</dependency>

@Agent(name = "my-agent", description = "What this agent does")
public class MyAgent {
  @Prompt
  public void onMessage(String message, StreamingSession session) {
    session.stream(message);
  }
}

Repo: langgraph4j/langgraph4j, LangGraph-style stateful agent graphs for Java (about 2.1k stars)

github.com/langgraph4j/langgraph4j · latest 1.9.10

LangGraph4j builds stateful, multi-agent LLM apps as graphs in Java 17+. It supports cyclical graphs, conditional edges, checkpoints with several database and file backends, subgraphs, parallel branches, streaming and a Studio web UI, and it works with both LangChain4j and Spring AI.

💡 Why it matters to you: It lets you reuse the LangGraph concepts you are learning in Python on the Spring stack, which makes a good bridge tutorial.
Read deeper

Graphs can be exported as PlantUML or Mermaid diagrams. The 1.8.x line is kept as an LTS branch for fixes, and the README says exact signatures live in the examples, so start from those. Ollama chat models work in the Spring AI and LangChain4j integrations.

Compare it with Embabel (Paper 1) before choosing: graphs give explicit control, goal-oriented planning gives less wiring.

var graph = new StateGraph<>(SCHEMA, MyState::new)
    .addNode("greet", node_async(state -> Map.of("messages", "Hello")))
    .addEdge(START, "greet")
    .addEdge("greet", END)
    .compile();
GraphResult result = graph.invoke(Map.of()).join();

Learn today: the transactional outbox pattern in Spring Boot

Evergreen · reference: Gunnar Morling's 'Revisiting the outbox pattern'

Write the business row and an 'outbox' row in the same database transaction, then let a separate publisher send outbox rows to Kafka and mark them sent. That removes the dual-write problem where the database commits but the broker call fails, or the other way round.

💡 Why it matters to you: It is core microservices interview material and a direct match for your Spring Boot, JPA and Kafka stack.
Read deeper

Consumers must be idempotent, because the publisher can send a row twice after a crash: use the event id as a deduplication key. Start with polling for simplicity; change data capture with Debezium is the option when volume grows. Delete or archive sent rows on a schedule.

Practice: add an outbox table to a small Order service, kill the app between commit and publish, and prove the event still goes out after restart.

@Transactional
public Order place(OrderRequest r) {
  Order o = orders.save(new Order(r));
  outbox.save(new OutboxEvent(UUID.randomUUID(), "order.placed", json(o)));
  return o; // one commit covers both rows
}

@Scheduled(fixedDelay = 1000)
public void publish() {
  for (OutboxEvent e : outbox.findTop100BySentFalseOrderById()) {
    kafka.send("orders", e.getId().toString(), e.getPayload()).join();
    e.markSent(); outbox.save(e);
  }
}
