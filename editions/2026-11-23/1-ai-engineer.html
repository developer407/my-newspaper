Local models and serving

Ollama 0.40.17: Inkling 2 Mini on Apple silicon, and MCP tools loaded on demand

Ollama GitHub release v0.40.17 · Nov 21, 2026

Ollama 0.40.17 adds Inkling 2 Mini (26B parameters, Apple silicon only for now) and lets Apple silicon serve concurrent requests. `ollama launch claude` now loads MCP tools on demand instead of all at start, and Vulkan uses mmap on integrated GPUs, which fixes load failures.

💡 Why it matters to you: Concurrent requests on a Mac make local Spring AI integration tests and multi-agent demos much less painful, and on-demand MCP tool loading keeps the prompt small.
Read deeper

The release candidates show where the work went: rc1 batches speculative-decoding verification in the MLX runner so drafting stays active under concurrent generation, and rc2 sizes the saved Metal prefix history to observed memory headroom instead of a fixed 8 GiB and frees cold history under memory pressure. Turning thinking off now maps to the lowest supported reasoning level, and source builds can use prebuilt MLX-C and XGrammar binaries.

For a Spring AI app nothing changes in code: you point the Ollama starter at the new model tag. The practical win is that two agents (or an agent plus an embedding job) can share one Mac without queueing.

spring.ai.ollama.base-url=http://localhost:11434
spring.ai.ollama.chat.options.model=<model-tag-you-pulled>
# pull first:  ollama pull <model-tag-you-pulled>

vLLM 0.34.0: Model Runner V2 only, extensible KV cache by default, block size 64

vLLM GitHub release v0.34.0 · Nov 18, 2026

vLLM 0.34.0 has 1,061 commits from 412 contributors and 10 new models, including Mistral Large 4 and MiniMax-M3.1-Flash. Model Runner V1 is gone, so Model Runner V2 is the only GPU runner, and the extensible KV cache is on by default.

💡 Why it matters to you: If you self-host an open model behind Spring AI's OpenAI-compatible client, this release changes your launch flags and defaults, so read it before bumping the image.
Read deeper

The extensible KV cache sizes itself from the memory that is free after warmup, so most users should delete gpu_memory_utilization from their configs. The default block size changes from 16 to 64. ROCm 7.2 images and wheels are no longer published, and huggingface_hub 2.0.0 or newer is required.

Removed in this release: QuTLASS/fp_quant, Marlin W4A8 and the Keye-VL models. The notes also report up to 1.95x decode on Step5 (GB200) and 1.6x throughput on GLM-5.3-Flash on Blackwell and MI355X, which are the project's own figures.

# before (0.33 and earlier)
vllm serve <model> --gpu-memory-utilization 0.90 --block-size 16
# 0.34: drop the memory flag, block size defaults to 64
vllm serve <model>

Transformers 5.24.0: Inkling 2 Mini, Sarvam architectures and a cache rename

Hugging Face Transformers release v5.24.0 · Nov 21, 2026

Transformers 5.24.0 adds Inkling 2 Mini, Apertus 1.5, Omnilingual ASR (1,600+ languages), Dory, HY4-VL and the SarvamMLA and SarvamMoE architectures behind Sarvam's 105B and 30B models. It also renames past_key_values and cache_params to cache.

💡 Why it matters to you: Sarvam support in the main library means Indian-language models are easier to load for RAG and chatbot tutorials, and the cache rename can break your custom generation code.
Read deeper

The old argument names keep working with a deprecation warning until v5.40.0 for forward and v6.0.0 for generate. peft 0.22.0 or newer is now required, modeling_attn_mask_utils.py is removed (remote-code models must import from transformers.masking_utils), and pickled .pt2 programs now need trust_remote_code=True.

Lara Mini is released under a non-commercial license in a gated repository, so check licenses before using it in a course project.

Research and startups

Paper explained: LAMB keeps competing hypotheses as latent beliefs for long-horizon agents (older, Oct 2026)

arXiv 2610.26955 · submitted Oct 2026 (ID suggests October; summary search-sourced)

LAMB is a recurrent memory design for LLM agents that stores competing guesses about hidden world state as latent vectors, not written notes. The authors report gains on ALFWorld, BabyAI, ScienceWorld and Crafter over a baseline called PABU.

💡 Why it matters to you: It is a different answer to the 'agent memory' problem that your Spring AI Session API and LangGraph checkpoints solve with text, and a good topic for a tutorial that compares the two.
Read deeper

A Common-Delta factorization combines a shared Common state (interaction evidence) with weighted Delta components for the competing hypotheses, and hypotheses are updated by how well the agent's action-outcome predictions match what happens. Reported numbers: +6.0 points on ALFWorld SR@30, +22.0 on ScienceWorld success, +26.37 on Crafter achievement progress and 17.70 points fewer redundant actions on ALFWorld.

These are the authors' own results and I only saw the abstract-level summary, so treat the details as unverified until you read the paper.
