Maven 3.10.1 and 3.10.2: no more JLine, optional profiles with -P ?, and build-extension fixes

Apache Maven GitHub releases · Nov 15 and Nov 22, 2026

Maven 3.10.1 (Nov 15) drops JLine and emits ANSI colours directly, accepts a ? prefix for optional profiles in -P, honours quotes in MAVEN_ARGS and reads the encryption password from standard input when there is no console. Maven 3.10.2 (Nov 22) is bug fixes only, including ANSI colours on Windows 11 terminals without WT_SESSION and build extensions overriding core lifecycle mappings again.

💡 Why it matters to you: The `-P ?profile` form is handy for CI scripts shared between Spring Boot modules where not every module defines every profile, and 3.10.2 is the safer pin for Windows laptops.
Read deeper

Other 3.10.1 items: recursion detection for custom root directory aliases, Windows and Cygwin path handling, and treating loopback hosts as local for mirror rules. 3.10.2 also fixes cached imported dependency management, respects plugin-level inherited=false when executions exist, reports well-formed but invalid POMs as invalid rather than malformed, and gives a clear error for an unparsable extensions.xml. Dependency updates include Resolver 2.0.26.

If you use the Maven wrapper in your Spring Boot projects, bump distributionUrl in .mvn/wrapper/maven-wrapper.properties and run a clean build before committing.

# optional profile (per the 3.10.1 notes): the build does not fail if it is missing
mvn -P '?ci-extras' verify

# .mvn/wrapper/maven-wrapper.properties
distributionUrl=https://repo.maven.apache.org/maven2/org/apache/maven/apache-maven/3.10.2/apache-maven-3.10.2-bin.zip

Xen Orchestra CVE-2026-133469 (CVSS 9.8): an empty-object login token gives unauthenticated Admin access

GitHub Advisory GHSA-2r3w-c2vx-fv5g · published Nov 20, added to the advisory database Nov 23, 2026

A critical authentication bypass in Xen Orchestra's REST API lets a crafted authentication cookie make the server accept a login token it should reject. The cookie parser turns it into an object, the signIn method does not check the type of its credentials and the token lookup treats an empty object as "no filter", returning the first stored token.

💡 Why it matters to you: It is a textbook type-confusion bug that also fits JS backends you may write: always validate that a credential is a string before using it in a database lookup.
Read deeper

The advisory says an adversary can bypass authentication and act with Admin privilege, and notes that compromising Xen Orchestra can lead to code execution on managed pools and takeover of XCP-ng hosts as root. Affected is xo-server (npm) 5.7.4 and earlier, rated CVSS 3.1 9.8, classified as CWE-287 and CWE-1287.

The advisory lists no patched version, but it references fix commit 50166fe, pull request #10748 and Vates advisory VATES-SA-2026-062. The metadata looks out of date, so confirm the fixed release with Vates, and until then restrict access to the management interface and check for unexpected admin tokens.

// the bug pattern, in plain Node terms: a "token" that is not a string
const token = req.cookies.authenticationToken;
if (typeof token !== "string" || token.length === 0) {
  throw new Error("invalid credentials");   // reject objects, arrays, empty values
}
const record = await tokens.findOne({ id: token });

Fabio CVE-2026-104099 (CVSS 9.1): path variants like /./admin/ slip past per-route ACLs

GitHub Advisory GHSA-4hrh-34w3-5ww8 · published Aug 9, NVD Nov 19, updated Nov 20, 2026

The Fabio load balancer selects routes using the raw request path without normalising it, and per-route IP ACLs and basic-auth checks depend on the chosen route. A path such as /./admin/, /%2e/admin/, //admin/ or /x/../admin/ can match a less restrictive catch-all route, and the backend then normalises the path and serves the protected resource without credentials.

💡 Why it matters to you: The same class of bug can hit any gateway in front of Spring Boot, including Spring Cloud Gateway or Nginx rules, so test your path-based security rules with encoded and dotted paths.
Read deeper

Fabio before 1.7.3 is affected, and the fix is to upgrade to 1.7.3. It needs a fallback route to the same backend, which matches the two-tag urlprefix- configuration in Fabio's access-control docs. The advisory recommends normalising the path with dot-segment decoding and path.Clean before route lookup, and lowercasing the host.

It also notes two secondary issues: X-Forwarded-Prefix is passed through from clients on non-strip routes, and the gRPC proxy path never calls the ACL or auth gates. The Aug 9 publication date means the NVD entry (Nov 19) is what is new this week.

# quick check against your own gateway: both should return 401/403, not 200
curl -i http://gateway.local/admin/
curl -i "http://gateway.local/%2e/admin/"
curl -i "http://gateway.local//admin/"
curl -i "http://gateway.local/x/../admin/"

JLine ReDoS CVE-2026-77423: crafted search patterns in the less viewer can pin a thread (fixed in 3.30.15 and 4.3.1)

GitHub Advisory GHSA-2v9w-34q6-wpqx · maintainer Jun 30, NVD Sep 23, GitHub database Nov 23, 2026

The less pager in jline-builtins passes user-entered search patterns straight to Pattern.compile() with no limit on complexity or run time, so nested quantifiers can cause catastrophic backtracking. The advisory is rated High (CVSS 3.1 7.5, availability only) and affects versions below 3.30.15 and 4.0.0 up to 4.3.1.

💡 Why it matters to you: JLine is a transitive dependency of many Java CLI tools and shells, so check your dependency tree; a Spring Boot web service is only at risk if it exposes a JLine terminal over Telnet or SSH.
Read deeper

In Telnet or SSH deployments a crafted pattern can tie up a session and possibly exhaust a bounded session pool. The same issue reportedly affects the & display-filter path. The advisory suggests a linear-time engine such as RE2/J, or a worker with a strict timeout as a fallback.

The fixed versions are 3.30.15 and 4.3.1. Most Java developers will meet JLine through build tools and shells, so the practical step is mvn dependency:tree and an upgrade where it appears.

mvn dependency:tree -Dincludes=org.jline
