Claude Code 2.1.331: Code Mode on every cloud provider, and `claude doctor` tests your API connection

Claude Code GitHub release v2.1.331 · Nov 23, 2026

Claude Code 2.1.331 adds Code Mode to terminal sessions on Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry and Claude Platform on AWS. `claude doctor` now includes an API connectivity check that reports the HTTP status or error, and a new CLAUDE_CODE_DISABLE_RESPONSE_COMPRESSION setting helps behind proxies that cut off compressed responses.

💡 Why it matters to you: If you run Claude Code behind a corporate proxy or through a cloud provider, `claude doctor` now tells you whether the network or the key is the problem, and the compression switch is the first thing to try when replies arrive truncated.
Read deeper

The same release lets plugin manifests declare optionalDependencies and fixes MCP tool calls that could hang for up to 30 minutes on some malformed replies. That last fix matters for anyone wiring Claude Code to home-grown MCP servers, because a hung call used to look like a frozen session.

The previous release, 2.1.330 (Nov 20), added organisation sign-in and a built-in chart mod and was covered in an earlier edition. The notes shown on the release page were cut off, so check the full changelog for the complete list.

Microsoft Copilot SDK: the Copilot CLI agent runtime as a library, with a Java SDK

microsoft/copilot-sdk on GitHub (trending on Java) · Nov 24, 2026

The Microsoft Copilot SDK, formerly the GitHub Copilot SDK, exposes the agent runtime behind Copilot CLI so you can invoke planning, tool use and file edits from code. It supports Node.js, Python, Go, .NET, Rust and Java, with Java published as com.microsoft:copilot-sdk, and it can use your own keys for OpenAI, Microsoft Foundry or Anthropic.

💡 Why it matters to you: A Java SDK means you can embed a coding agent inside a Spring Boot service, for example a bot that reviews pull requests, without shelling out to a CLI.
Read deeper

SDK v2 loads a native Rust runtime in-process through a C ABI, or you can run it as a child process or a standalone server over TCP. By default it exposes the Copilot CLI's first-party tools, a permission handler per SDK decides what may run, and you can add custom agents, skills, tools and MCP servers.

A Copilot subscription is required unless you bring your own keys, and the Java README needs a platform runtime classifier dependency. The repository page shows no published release, so check the CHANGELOG before adopting it.

OpenAI Agents SDK 1.0.0-alpha.2: resume conversations and pending approvals across workers

openai-agents-python GitHub releases · Nov 23, 2026

Agents SDK 1.0.0-alpha.2 lets you resume conversations and pending approvals on a different worker, with Responses or Codex. It adds tool execution hooks, opt-in Runner text redaction and detailed tracing. It also introduces new persisted state formats, and alpha.1 cannot read the new snapshots.

💡 Why it matters to you: Resumable approvals are what a human-in-the-loop flow needs when a web request ends before a person clicks approve, the same problem Spring AI tackles with its session and tool-confirmation work.
Read deeper

The release notes give one clear upgrade rule: upgrade checkpoint readers before writers, otherwise old workers will fail on new snapshots. Alpha.1 (Nov 20) added Codex as an opt-in model provider through CodexProvider, embedding Codex Core via PyO3 and distributed only through GitHub Releases.

The current stable line is 0.25.0 (Nov 18), which removes the beta Runloop sandbox provider, changes the default compaction model to gpt-6-luna and allows concurrent requests on MCP v2 Streamable HTTP. Pre-releases like these are for trying out, not for production.

Spring AI and the JVM

Spring AI ACP Harness Client 0.7.0: one interface to drive Goose, Codex, OpenCode or Gemini CLI

spring-ai-community/spring-ai-acp-harness-client on GitHub · updated Nov 13, 2026

The Spring AI ACP Harness Client is a library for driving coding agents over the Agent Client Protocol from Spring Boot. Application code uses one AcpHarnessClient interface, and a single property chooses Goose, Codex, OpenCode or any agent in the ACP registry, demonstrated with Gemini CLI. Version 0.7.0 is on Maven Central.

💡 Why it matters to you: It turns "run a coding agent" into a Spring bean, which is a clean base for a PR-review bot or a migration helper, and it needs Java 21, Spring Boot 4.1.x and Spring AI 2.x.
Read deeper

You add one runtime starter, set spring.ai.acp.harness.runtime and a model, then call prompt().session(...).user(...).call().content() or stream events as a Flux. There is also a ChatModel adapter. Registry-provisioned agents are downloaded, checked against their published SHA-256 and launched; other agents must be installed and authenticated locally.

One caution from the project: setting permissions.policy to deny does not by itself stop an agent from writing files. Also set the mode to plan so the agent asks for permission and the policy can refuse it.

<dependency>
  <groupId>org.springaicommunity</groupId>
  <artifactId>spring-ai-acp-harness-client-boot-starter-goose</artifactId>
  <version>0.7.0</version>
</dependency>

# application.yml
spring:
  ai:
    acp:
      harness:
        runtime: goose   # codex, opencode, or gemini (registry)

// Java
String out = acpHarnessClient.prompt()
        .session("review-123")
        .user("Inspect this change")
        .call().content();

Spring AI MCP Security 0.1.14: OAuth2, API keys and DNS-rebinding checks for MCP servers and clients

spring-ai-community/mcp-security on GitHub · updated Nov 23, 2026

The mcp-security project adds authorization to MCP servers and clients built with Spring AI: OAuth 2.0 protection or API keys on servers, Origin and Host header validation against DNS rebinding, client flows for authorization code, client credentials and hybrid, Dynamic Client Registration, and an authorization server with DCR and client ID metadata documents. Version 0.1.14 targets Spring AI 2.0.x.

💡 Why it matters to you: This is the Spring-native answer to the MCP DNS-rebinding advisories (Jupyter MCP, Todoist MCP) that hit other stacks this month, and it takes a few lines to secure a server you already run.
Read deeper

On a Spring Boot server you add org.springaicommunity:mcp-server-security-spring-boot:0.1.14 and set spring.security.oauth2.resourceserver.jwt.issuer-uri; auto-configuration then secures all endpoints. To protect only tool calls, enable method security and put @PreAuthorize on the tool methods. OAuth2 and API keys need Spring WebMVC, while the Origin and Host validation also works on WebFlux.

On the client side, add mcp-client-security-spring-boot and set spring.ai.mcp.client.initialized=false so start-up does not make unauthenticated calls. Spring AI 1.1.x users should use version 0.0.6 instead.

<dependency>
  <groupId>org.springaicommunity</groupId>
  <artifactId>mcp-server-security-spring-boot</artifactId>
  <version>0.1.14</version>
</dependency>

# application.properties
spring.security.oauth2.resourceserver.jwt.issuer-uri=https://auth.example.com

// secure only the tool calls: enable method security, then annotate your existing tool method
@PreAuthorize("isAuthenticated()")
public Order lookup(String id) { ... }

Spring AI Decision Extensions: LLM-as-judge, self-refine and guardrails on the DecisionModel API

spring-ai-community/spring-ai-decision-extensions on GitHub · updated Nov 20, 2026

Decision Extensions packages advisors built on the DecisionModel API from Spring AI 2.1: DecisionJudge scores an answer against several criteria in one call, DecisionSelfRefineAdvisor retries a failed response with the defect as feedback, and DecisionGuardrail checks input and output against a set of hazards. It replaces the archived spring-ai-typesafe project.

💡 Why it matters to you: You get cheap, typed quality gates for a RAG answer (score it, retry once, or escalate) without parsing free-text from a judge model.
Read deeper

Patterns include DecisionConfidenceGate (act, confirm or escalate), DecisionConsistency (variation across repeated samples) and DecisionCompositeScore. An experimental DecisionChatModel exposes a decision model as a ChatModel so ChatClient.entity(...) can return typed classifications, and StubDecisionModel supports offline tests.

It works with any provider that implements the DecisionModel API, such as OpenAI, Ollama or System One. It is not yet released (the BOM shows 0.6.0-SNAPSHOT) and needs Spring AI 2.1.0 or later and Java 17+.

Spring AI Playground: build and test MCP tools locally, and only expose the ones that pass

spring-ai-community/spring-ai-playground on GitHub · updated Nov 3, 2026

Spring AI Playground is a desktop and Docker app for building, testing and serving MCP tools. Its rule is "No pass, no run": a new tool starts as a draft and reaches the built-in /mcp server and chat only after it passes a local test run, with an allowlist, SSRF-guarded fetch and per-tool risk levels from L0 to L5.

💡 Why it matters to you: It is a ready-made workbench for MCP tools you want to demo in a tutorial, and it can export validated tools as a standalone MCP server bundle that runs in Docker.
Read deeper

Other features: agentic chat with RAG and human approval for sensitive calls, a vector database with an ETL pipeline studio, an MCP proxy for external servers, dashboards for tokens, cost and tool calls, and secret masking. Providers are Ollama, OpenAI and OpenAI-compatible APIs, and you can start with spring.ai.model.chat=none to run only the tool runtime.

The README says the sandbox is defense-in-depth, not adversarial-grade isolation, and that outside code contributions are not being accepted right now. The next target is 1.0.0.

Paper tool: Google's PaperOrchestra turns rough notes and experiment logs into a LaTeX manuscript with agents

google-research/paper-orchestra on GitHub (trending) · Nov 24, 2026

PaperOrchestra is a multi-agent framework from Google Cloud AI Research that turns unconstrained pre-writing materials, meaning ideas and experimental logs, into submission-ready LaTeX manuscripts. Agents handle the outline, literature review, section writing, refinement and plots, and the output follows a target conference template such as CVPR 2025.

💡 Why it matters to you: It is a worked example of a multi-agent pipeline with clear stages, the same shape you could build in LangGraph or Spring AI for report-writing.
Read deeper

The literature agent searches for and integrates relevant papers, and plotting is opt-in through a flag. The README gives no benchmark numbers, only an autoraters directory for automated evaluation, and it cites the paper as arXiv 2604.05018. The dataset is not included yet and the repository says it is not an officially supported Google product.

Read it for the architecture, not for quality claims: the README does not report scores, so judge the output on your own examples.
