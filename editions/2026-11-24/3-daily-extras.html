AI tools of the day

Tool: Goose 1.60.2, an open-source agent that now has a skill operation, Gemini 4 Neon and a leaner core

Goose GitHub releases v1.60.0 to v1.60.2 · Nov 17 to Nov 20, 2026

Goose 1.60.0 (Nov 17) replaces the Skills extension with a skill operation, adds operations for executable commands, slash commands, bang commands and steering, and adds Cortecs and Onysoft providers. 1.60.1 stops compaction from including the <analysis> scratchpad that Claude models refuse, and 1.60.2 (Nov 20) adds Gemini 4 Neon to the model catalog and sends thinking levels, including xhigh, to Gemini 4 and later.

💡 Why it matters to you: Goose is one of the agents the Spring AI ACP Harness Client can drive, so it is an easy way to try "agent as a Spring bean" without paying for a hosted tool.
Read deeper

1.60.0 also fixes the developer shell, cron validation for schedules, Ollama tool-call arguments, OpenAI tool choice, Databricks thinking blocks and Windows ZIP updates. It separates platform extensions from the MCP runtime, removes chat mode and the `goose review` subcommand, and raises the minimum Rust version to 1.95.0 and Electron to 45.2.3 with macOS 13 as the new minimum.

If you used `goose review`, plan a replacement before upgrading. Ollama tool-call argument fixes make it a reasonable agent for local models.

Tool: Google's Stitch skills, agent skills that turn Stitch designs into React, Vite dashboards and shadcn/ui

google-labs-code/stitch-skills on GitHub (trending) · Nov 24, 2026

stitch-skills is an Apache-2.0 library of Agent Skills for Google Stitch that works with Codex, Antigravity, Gemini CLI, Claude Code, Cursor and OpenCode. Plugins cover design (code-to-design, generate-design, manage-design-system), build (react-components, react-native, shadcn-ui, react-vite-dashboard, remotion) and utilities such as design-md, enhance-prompt and stitch-loop.

💡 Why it matters to you: It is a ready-made way to go from a UI idea to React components with Vite and shadcn/ui, which suits your React side and a "build a dashboard" tutorial.
Read deeper

The skills are instructions that direct the agent to use the Stitch MCP server, which must be registered and running with credentials from Stitch's MCP setup guide. Without it, they do nothing. Install with `npx plugins add google-labs-code/stitch-skills --scope project --target claude-code`, or `--target cursor` for Cursor, or `codex plugin marketplace add google-labs-code/stitch-skills --ref main` for Codex.

The README says it is not an officially supported Google product, and skills have interdependencies, so install every required dependency when selecting skills one by one.

# Claude Code
npx plugins add google-labs-code/stitch-skills --scope project --target claude-code
# Cursor
npx plugins add google-labs-code/stitch-skills --scope workspace --target cursor

Tool: AutoClip, an open-source clipper that turns a long video into ranked short clips with subtitles and covers

zhouxiaoka/autoclip on GitHub (trending, about 14.5k stars) · Nov 24, 2026

AutoClip is an MIT-licensed tool that takes a video link, gets subtitles from captions or Whisper or SenseVoice transcription, has an analysis model score candidate segments, and produces up to 10 clips per platform with subtitles, a cover, a title, a description, hashtags and a ZIP publishing package. Analysis can use a cloud API with your own key or a local model through Ollama or LM Studio.

💡 Why it matters to you: For tutorial creators it is a free way to cut a two-hour coding stream into Shorts, and the local-model option keeps transcripts on your machine.
Read deeper

It runs as a desktop app (macOS Apple Silicon and Windows x64, not code-signed), through Docker (web UI on port 3000) or from a CLI and MCP server (`uvx autoclip-mcp`). The README gives an example of about 0.09 yuan in text-model usage for a 1h43m English video with author subtitles, excluding transcription and image generation.

The project is maintained by one person with no guaranteed response time, and cloud analysis sends your subtitles to the provider, while cloud transcription uploads audio. Anonymous telemetry can be turned off in settings.

autoclip produce talk.mp4 --srt talk.srt --platform douyin --portrait-style podcast --json

GitHub repos of the day

Repo: HKUDS/CLI-Anything, generate agent-ready command-line interfaces for existing software (about 63.7k stars)

HKUDS/CLI-Anything on GitHub (trending, +790 stars today) · Nov 24, 2026

CLI-Anything is an Apache-2.0 project that has a coding agent run a 7-phase pipeline (analyse, design, implement a Click-based CLI, plan tests, write tests, document, publish) to produce a command-line interface an AI agent can use. CLIs have a REPL, subcommands and a --json flag, and where possible call the real application backend, such as headless LibreOffice or Blender's Python API.

💡 Why it matters to you: It is a pattern for making any tool agent-friendly, including an internal Spring Boot admin API, and CLI-Hub gives you ready-made harnesses to try first.
Read deeper

The README lists dozens of harnesses: GIMP, Blender, Inkscape, Krita, Audacity, Kdenlive, OBS Studio, LibreOffice, Zotero, Obsidian, n8n, Draw.io, Mermaid, FreeCAD, QGIS, Godot, ComfyUI, Ollama and more. The generator works with Claude Code, Cursor, Codex, OpenCode and other SKILL-compatible agents.

Generated CLIs are only as good as the agent and tests behind them, so check the test phase output before trusting one with destructive operations.

pip install cli-anything-hub
cli-hub search image
cli-hub install gimp
cli-hub launch gimp

# or generate one in Claude Code
/plugin marketplace add HKUDS/CLI-Anything
/plugin install cli-anything
/cli-anything ./gimp

The README example uses a DashScope key and model, and the page shows no published release, so pin to a commit if you try it.

Idea: turn a Spring Boot admin API into a secured MCP server, then test it in Spring AI Playground

Idea inspired by the Spring AI MCP Security release · Nov 24, 2026

Pick one internal Spring Boot API (orders, users or tickets), expose three read-only operations and one write operation as MCP tools, and protect them with OAuth2 using the Spring AI MCP Security starter. Test each tool in Spring AI Playground, which only exposes tools that pass a local test run.

💡 Why it matters to you: It combines three things from this week's news into one tutorial: MCP, Spring Security, and safe tool design, with a clear before-and-after on security.
Read deeper

Add a risk level to each tool (read, write, spend) and require human approval for anything above read. Then show an attack: a web page that tries DNS rebinding against a local MCP server with and without Origin and Host validation, as seen in the Jupyter MCP and Todoist MCP advisories this month.

Finish by connecting the server to a coding agent such as Goose or Codex through the ACP harness, and record the session for a video.

Idea: a "ask my course" bot that answers student questions with timestamped links into your tutorial videos

Transcribe your tutorial videos (Whisper, or the captions you already have), chunk the transcripts with timestamps, embed them into pgvector or Weaviate, and build a Spring AI chat endpoint that answers a question and returns the three best timestamps as links. A small React widget on your course page completes it.

💡 Why it matters to you: It gives your audience a reason to come back, shows RAG end to end in a product you own and is easy to demo on camera.

Use Spring AI session memory for follow-up questions and a decision-model judge to check that an answer is actually supported by the retrieved chunks before showing it. For multi-tenant courses, Weaviate 1.41 namespaces or a tenant column in pgvector keep each creator's data separate.

Measure it: keep 30 real student questions as a fixed test set and rerun them whenever you change chunking or the embedding model.

Learn today: put a risk-based approval gate in front of every agent tool call

Technique, grounded in Spring AI Playground risk levels, Spring AI Session Extensions and the Agents SDK 1.0 alpha · Nov 24, 2026

Give each tool a risk level (read, write, spend, destructive), run reads automatically, and park anything above that until a person approves. Log every decision with who approved, when and what the arguments were, and cap spending per session.

💡 Why it matters to you: It is the one control that makes an agent safe enough to demo, and this week's releases (Spring AI session turns, Agents SDK resumable approvals, session spending limits) all point the same way.
Read deeper

The mechanics are the same in any stack: classify the tool, decide, and if approval is needed save the pending call and its arguments, return "waiting for approval" to the model, and resume when the human answers. Spring AI Session Extensions parks turns for this, OpenAI Agents SDK 1.0 alpha.2 can resume pending approvals on another worker and Spring AI Playground labels tools L0 to L5.

The sketch below is plain Java written for this paper, not a Spring AI API. Wire it into whichever tool-calling hook your framework offers, and test the deny path as carefully as the allow path.

enum Risk { READ, WRITE, SPEND, DESTRUCTIVE }

record ToolCall(String tool, Risk risk, String args, double cost) {}

sealed interface Decision permits Run, Park, Deny {}
record Run() implements Decision {}
record Park(String reason) implements Decision {}
record Deny(String reason) implements Decision {}

Decision decide(ToolCall c, double spentThisSession, double sessionCap) {
    if (spentThisSession + c.cost() > sessionCap) return new Deny("session budget reached");
    return switch (c.risk()) {
        case READ -> new Run();
        case WRITE, SPEND -> new Park("needs approval");
        case DESTRUCTIVE -> new Deny("never automatic");
    };
}
