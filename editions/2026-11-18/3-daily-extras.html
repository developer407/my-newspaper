Tool: LangGraph 1.2.22 — child graphs stream on their own thread, plus checkpoint and message speed-ups

GitHub releases (langchain-ai/langgraph) · 2026-11-14

LangGraph 1.2.22 was released on 14 Nov. It fixes streaming so a child graph runs on its own thread when the caller streams subgraphs, and skips message conversion in add_messages for plain messages. The same day, langgraph-checkpoint-postgres 3.2.1 landed with Postgres checkpointer performance fixes.

💡 Why it matters to you: If you are learning LangGraph, a Postgres checkpointer is the usual way to make agent runs resumable, and this release makes both paths cheaper.
Read deeper

The release notes list three changes: the subgraph-streaming fix, performance work such as skipping message conversion in add_messages for plain messages and doing less work on wide states, and a lighter error-message path in langgraph-prebuilt 1.1.2.

The Postgres checkpointer 3.2.1 runs a lone store read outside a pipeline, skips the async saver's lock for connection pools, and avoids a thread hop when no pending writes need loading. These are point-release fixes, not new APIs, so upgrading should be low risk, but read the full notes before bumping production.

Tool: Deep Agents — LangChain's batteries-included agent harness ships 0.7.39 and a terminal client

GitHub releases (langchain-ai/deepagents) · 2026-11-17

deepagents 0.7.39 (16 Nov) fixes streaming of asynchronous subagent runs and stores uploads containing NUL bytes as base64 in StoreBackend. The companion terminal package deepagents-code reached 0.2.10 on 17 Nov, loading MCP trust lists without blocking the server event loop. The repo describes itself as the batteries-included agent harness.

💡 Why it matters to you: It is a ready-made planning, subagent and file-system harness on top of LangGraph, a fast way to see what a production agent loop looks like before writing your own.
Read deeper

Deep Agents was introduced in March 2026 as an MIT-licensed framework with built-in planning, file access, sandboxed shell execution and context management (per an ascii.co.uk news write-up). The GitHub repo showed about 31.4k stars when searched today.

The latest releases are bug-fix and quality-of-life: async subagent streaming, base64 storage for binary-ish uploads, MCP trust-list loading, and a working upgrade command in the ACP import error. Good one to read if you want to compare it with Spring AI agent patterns.

Tool: Promptfoo 0.125 — stability reporting across repeated eval runs and a safe mode for inline JavaScript

GitHub releases (promptfoo/promptfoo) · 2026-10-23

Promptfoo 0.125.0 (23 Oct) added stability reporting across repeated tests, cache-hit disclosure in eval summaries, ROUGE-L and ROUGE-S assertions, trace-span filtering by attributes and a safe mode that disables inline JavaScript. It also made the Claude Agent and Codex SDKs opt-in, a breaking change. 0.125.1 followed on 25 Oct.

💡 Why it matters to you: Prompt evals in CI are the cheapest way to stop LLM regressions, and repeat-run stability is exactly what flaky model output needs.
Read deeper

Stability reporting runs the same test several times so you can see whether a pass is reliable or lucky. Cache-hit disclosure tells you when an eval result came from cache rather than a fresh model call.

Promptfoo's site says it is now part of OpenAI (a deal reported as announced 9 March 2026 by a secondary source). Check licence and roadmap before building a team process on it. It is a Node tool, so it works fine against a Spring Boot endpoint over HTTP.

📚 Learn this today

Learn: self-correcting structured output in Spring AI — validateSchema() and native provider schemas

Spring blog (Christian Tzolov), docs.spring.io · 2026-06-23

LLMs return text, and .entity() only asks for JSON matching a schema without enforcing it, so malformed output throws. Spring AI 2.0 adds validateSchema(), which auto-registers a recursive StructuredOutputValidationAdvisor that retries with the validation error appended (default 3 attempts), and useProviderStructuredOutput() for request-side enforcement.

💡 Why it matters to you: Reliable typed output is the base of every extraction, triage and agent-routing feature you will build.
Read deeper

Use validateSchema() for retry on bad output, useProviderStructuredOutput() to push the schema to the provider (OpenAI, Anthropic, Google GenAI, Mistral AI and Ollama per the post, model-specific), or both. Both are opt-in. .entity() works only with .call(), not .stream().

Gotchas from the post: native JSON Schema support is often partial ($ref, anyOf/oneOf and recursive types may fail), top-level arrays are not accepted by OpenAI native output so wrap a List in a record, and a custom converter only participates if it implements getJsonSchema().

record Triage(String category, String priority, String summary) {}

Triage t = chatClient.prompt()
    .user("Triage: 'App crashes on UPI payment screen'")
    .call()
    .entity(Triage.class, spec -> spec
        .useProviderStructuredOutput()
        .validateSchema());

// custom retries
var advisor = StructuredOutputValidationAdvisor.builder()
    .outputType(Triage.class)
    .maxRepeatAttempts(5)
    .build();
