Model releases

GPT-6.2 Astra and Sol land: OpenAI's new flagship pair, with Astra priced lower

OpenAI SDK release pages / press reports · Nov 17, 2026

OpenAI launched GPT-6.2 Astra (harder professional work) and GPT-6.2 Sol (everyday analysis, writing and coding) on Nov 17. Both are in ChatGPT Work and Codex for paid tiers and in the API as gpt-6.2-astra and gpt-6.2-sol; the official Python and Java SDKs added the identifiers the same day.

💡 Why it matters to you: If your Spring AI or Python RAG code pins a model name, you can now A/B GPT-6.2 Sol against your current default for cost and quality.
Read deeper

The SDK release notes are the firmest evidence: openai-python v3.53.0 and openai-java v4.107.0 (both Nov 17) add model identifiers for GPT-6.2 Astra, GPT-6.2 Astra Law (Responses) and GPT-6.2 Sol, plus two new Responses background windows (2-hour and 8-hour). Coding-tool changelogs moved too: OpenCode 2.3.1 added GPT 6.2 models to its ChatGPT picker and 2.3.2 fixed GPT-6.2 re-billing the system prompt as uncached input on every step.

Press coverage says Sol's API price is unchanged at $2 input / $10 output per million tokens, while reports conflict on Astra's price (one says a 20% cut to $8 / $40, another cites $10 / $50). OpenAI also reportedly says Astra is the first externally released model to hit the High threshold for AI self-improvement under its Preparedness Framework. Treat prices and benchmark claims as unverified until you read OpenAI's own pricing page; independent tests reportedly show smaller coding-agent gains than OpenAI's figures.

Claude Fable 5.2 and Mythos 5.2: same model, two safety profiles, $8 / $40 per million tokens

Anthropic · Nov 9, 2026

Anthropic released Fable 5.2 to everyone and Mythos 5.2 (same underlying model, without the cyber and biology safeguards) to vetted organizations. Fable 5.2 costs $8 input / $40 output per million tokens, with an optional fast mode at $16 / $80 that generates up to 2.5x faster. The API model ID is claude-fable-5-2.

💡 Why it matters to you: Anthropic itself recommends Opus 5.5 for most everyday coding; Fable 5.2 is for ambitious, long-horizon agent work you would orchestrate from your own code.
Read deeper

Anthropic's own numbers (system-card methodology) put Fable 5.2 at 49.1% on FrontierCode 2.0 at Xhigh effort versus 45.5% for Opus 5.5, 69.9% vs 62.3% on FrontierSWE v2, and 89.3% on OSWorld 2.1. It also says High effort roughly matches Opus 5.5's best FrontierCode score at about half the cost per task. These are vendor-reported results.

Practical design hint from the page: Fable 5.2 can act as an 'Advisor' to smaller models or an 'Orchestrator' that delegates simpler work, which maps neatly onto a LangGraph supervisor or a Spring AI multi-model setup. Mythos 5.2 is only available through the Cyber and Life Sciences Verification Programs; Claude Security (Enterprise) uses it to scan codebases. The page states no context window.

alibaba/open-code-review: a precision-first AI code reviewer (Apache-2.0, ~53.8k stars)

It works in GitHub Actions, GitLab CI and Gerrit, supports OpenAI- and Anthropic-compatible APIs, and has an MCP server and agent skills.

💡 Why it matters to you: A ready-made reviewer you could run on a Spring Boot repo in CI, or dissect as a design for hybrid deterministic-plus-LLM review.
Read deeper

The project's own benchmark claim (AACR-Bench, 50 repos, 200 PRs, 10 languages) is higher precision and F1 than Claude Code with the same underlying model at about one-ninth of the tokens, with lower recall as a deliberate trade-off. That is a self-reported result, so test it on your code.

Install: Git 2.41+, then npm install -g @alibaba-group/open-code-review; configure with `ocr config provider` and `ocr config model`, or use delegation mode to borrow your coding agent's model.

Spring AI and the JVM

Spring AI ACP Harness Client 0.7.0: drive Goose, Codex or OpenCode from a Spring Boot app

Spring AI Community (GitHub) / Spring Office Hours · Nov 13, 2026

A new spring-ai-community library lets a Java app drive coding-agent harnesses over the Agent Client Protocol with one AcpHarnessClient API; you switch between Goose, Codex (via codex-acp), OpenCode or any ACP-registry agent by changing spring.ai.acp.harness.runtime. It streams text, thoughts, tool calls and plans as a reactive Flux and can expose an agent as a Spring AI ChatModel.

💡 Why it matters to you: Directly useful: a Spring Boot service can orchestrate coding agents, with Micrometer timers per turn and per-user MCP OAuth.
Read deeper

It needs Java 21+, Spring Boot 4.1.x and Spring AI 2.x (Boot 3.x is not supported). Features include named sessions with list/load/resume/delete, negotiated options such as model and mode with an on-unsupported policy, SHA-256-checked downloads of registry agents, and an optional terminal console. It was covered on Spring Office Hours S5E29 on Nov 9.

Security caution from the README: permissions.policy: deny alone does not stop an agent writing files. You must also set the agent mode (for example plan) so permission requests are raised and then denied.

spring:
  ai:
    acp:
      harness:
        runtime: goose
        model: gpt-5.4-mini

String out = acpHarnessClient.prompt()
    .session("review-123")
    .user("Inspect this change")
    .call().content();

Spring AI Decision Extensions: judge, self-refine and guardrail advisors (not yet released)

Spring AI Community (GitHub) · Nov 15, 2026

spring-ai-decision-extensions builds on the new DecisionModel API from Spring AI 2.1.0 with a DecisionJudge that scores answers against weighted criteria in one call, a self-refine advisor that retries with the defect as feedback, and input and output guardrail advisors. It is still at 0.5.0-SNAPSHOT.

💡 Why it matters to you: Offers a Spring-native way to add LLM-as-judge evals and prompt-injection screening to a ChatClient pipeline.
Read deeper

Ordering matters by design: the input guardrail runs before chat memory and retrieval so a blocked message is never stored, while the output guardrail runs last, next to the model. Patterns include DecisionConfidenceGate (act, confirm or escalate) and DecisionConsistency (variation across repeated samples). StubDecisionModel allows offline tests.

Requires Spring AI 2.1.0+ and Java 17+. The README says it is not released yet, so treat the API as unstable.

Learn today: write a SKILL.md for your own Spring Boot conventions and test it with an agent

The AI Engineer (tutorial idea) · Nov 18, 2026
