AI tools of the day

Tool: Appwrite — an open-source backend with a hosted MCP server for coding agents

github.com/appwrite/appwrite (58.2k stars, BSD-3-Clause) · checked Nov 19, 2026

Appwrite is an open-source backend platform (auth, database, storage, functions) that describes itself as MCP and agent-first. A hosted MCP server at mcp.appwrite.io works with Cursor, Claude Code, Codex and VS Code using OAuth, and a local MCP server exists for self-hosted setups.

💡 Why it matters to you: You could use it as a quick backend for a React plus AI demo, with an agent operating the project through MCP instead of you clicking through a console.
Read deeper

Agent skills install with npx skills add appwrite/agent-skills, and you can generate an AGENTS.md file for your repo. Self-hosting runs through a Docker installer; the README example uses the image tag appwrite/appwrite:2.7.2 (the page does not label it the latest release).

Caveat: an MCP server with write access to a live project deserves the same care as any admin credential. Start with a test project.

docker run -it --rm \
  --publish 127.0.0.1:20080:20080 \
  --volume /var/run/docker.sock:/var/run/docker.sock \
  --volume "$(pwd)"/appwrite:/usr/src/code/appwrite:rw \
  --entrypoint="install" \
  appwrite/appwrite:2.7.2

Tool: Google Stitch design skills — turn a prompt into a design, then into React and shadcn code

github.com/google-labs-code/stitch-skills (10.4k stars, Apache-2.0) · checked Nov 19, 2026

A set of agent skills for Google Stitch that follow the Agent Skills standard and work with Codex, Gemini CLI, Claude Code, Cursor and OpenCode. Skills cover design (generate-design, extract-design-md), build (react-components, shadcn-ui, react-vite-dashboard) and utilities (enhance-prompt, design-md).

💡 Why it matters to you: It fits your React and shadcn stack: describe a dashboard, get a design, and let the agent produce components you can then wire to a Spring Boot API.
Read deeper

It needs the Stitch MCP server configured, and the README says it is not an officially supported Google product. For Claude Code install with npx plugins add google-labs-code/stitch-skills --scope project --target claude-code; for Codex use codex plugin marketplace add google-labs-code/stitch-skills --ref main.

Example prompts from the README: "Enhance this prompt: make a settings page" and "Scan /src and extract the design system into .stitch/DESIGN.md".

npx plugins add google-labs-code/stitch-skills --scope project --target claude-code

Tool: Arcane — a self-hosted web UI for managing Docker and Compose

github.com/getarcaneapp/arcane (9.8k stars, BSD-3-Clause) · checked Nov 19, 2026

Arcane is a self-hosted Docker management tool described as "Modern Docker Management, Designed for Everyone". It is built with Go, SvelteKit and TypeScript, and the main branch is v3 (the last 2.x release lives on the release/2.x.x branch).

💡 Why it matters to you: Handy for a home lab or a small VPS where you run Spring Boot, Postgres and Redis containers and want a UI for logs, images and Compose projects.
Read deeper

The repo page has no feature list or install snippet, so follow the docs at getarcane.app. It was also on GitHub Trending today.

As with any tool that talks to the Docker socket, run it only on machines you control and keep it off the public internet without authentication.

GitHub repos of the day

Repo: affaan-m/ECC — an agent harness with 72 agents, 327 skills and a security scanner

github.com/affaan-m/ECC (about 306.6k stars, MIT) · checked Nov 19, 2026

ECC is an open-source "agent harness performance optimization system" for Claude Code, Codex, OpenCode, Cursor and others. It bundles 72 specialized agents, 327 skills, 98 command shims, hooks, rules, memory and AgentShield, a scanner for prompts, hooks, MCP config, permissions and secrets.

💡 Why it matters to you: Read its hooks and skill layout to see how others structure agent workflows (plan, test, implement, review, verify) before you write your own for Spring AI projects.
Read deeper

Claude Code is the primary target and Codex has a native plugin, while Cursor and OpenCode are beta. The README advises one install method per harness, since stacking them can duplicate skills and hooks. The current release is 2.2.3 (2026-10-01) and it is maintained mainly by one person.

Treat a big bundle of hooks and agents as code you must review: they run with your permissions.

npx ecc-universal@2.2.3 setup
# or, inside Claude Code:
/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc

Repo: HKUDS/CLI-Anything — generate agent-friendly command-line interfaces for existing software

github.com/HKUDS/CLI-Anything (about 59.8k stars, Apache-2.0) · checked Nov 19, 2026

CLI-Anything generates command-line interfaces for existing software so AI agents can operate it, with a --json flag for structured output and a REPL. It includes harnesses for GIMP, Blender, LibreOffice, Inkscape, OBS Studio, Zotero and Draw.io, and a CLI-Hub registry.

💡 Why it matters to you: The pattern (CLI plus SKILL.md plus JSON output) is a simple way to expose your own Spring Boot admin tasks to a coding agent without a full MCP server.
Read deeper

The generator runs a seven-phase pipeline: analyze the source, design command groups, implement a Click-based CLI, plan tests, write tests, document and publish as an installable package. In Claude Code you run /cli-anything ./gimp.

Each harness ships a SKILL.md that agents can discover, and plugins or skills exist for Claude Code, Cursor, Codex and OpenCode.

pip install cli-anything-hub
cli-hub install gimp
cli-hub launch gimp
cli-anything-gimp --json layer add -n "Background" --type solid --color "#1a1a2e"
  • Original: CLI-Anything on GitHub

Repo: cursor/plugins — the Cursor plugin spec with 100+ official plugins

github.com/cursor/plugins (about 17.2k stars, MIT) · checked Nov 19, 2026

The repository holds the Cursor plugin specification and a marketplace of official plugins for developer tools, frameworks and SaaS products. Each plugin has a .cursor-plugin/plugin.json manifest and can include skills, rules and mcp.json.

💡 Why it matters to you: It is a clean template for packaging your own skills, rules and MCP config, which you could teach in a video on building plugins for AI IDEs.
Read deeper

The root .cursor-plugin/marketplace.json lists all plugins. Each plugin directory can hold skills/ (SKILL.md with frontmatter), rules/ (.mdc files), mcp.json, README.md, CHANGELOG.md and LICENSE.

Listed examples include ralph-loop, github and hubspot, and a teaching plugin for skill mapping, practice plans and learning retrospectives.

Idea: a bring-your-own-Claude-plan app using linked billing

Builds on the Nov 17 Claude Platform linked-billing beta

Build a small AI SaaS where each customer links their own Claude organization and pays for their own usage, so you carry no inference cost. Spring Boot proxies the calls, React shows spend and a link/unlink screen.

💡 Why it matters to you: A teachable project: auth, a proxy service, per-user policy and a clear cost story that hobby developers care about.
Read deeper

Stack: Spring Boot 4 with a thin Claude client, Postgres for users and transcripts, React with shadcn for the settings page. Learn the beta header user-profiles-billing-2026-10-01 and billing_policy before you start.

Risks: it is a beta, it only works for customers whose organization pays Anthropic directly, and message threads expire after 5 minutes, so store transcripts yourself. A good video arc: build it, break it, and show the spend cap.

  • Related: Spring Boot releases

Idea: nightly RAG regression checks as a Docker Compose job

Builds on Docker Compose 5.8.0 jobs

Run a small evaluation script every night with the new Compose jobs element against your pgvector RAG service, and alert when answers drift. Use docker compose run for a manual trigger.

💡 Why it matters to you: It turns "evals" from a talk topic into a working pipeline for a Spring AI project, and shows a use for Compose jobs.
Read deeper

Scheduling needs Docker Engine 29.10 or later with the jobs extension; manual jobs work on any engine, so you can start with docker compose run and add scheduling later.

Suggested pieces: a fixed set of 20 questions with expected sources, a runner that logs scores to Langfuse, and a Slack or email alert. Use plain assertions plus an LLM judge, as the comparison paper in the AI Engineer paper suggests.

Learn today: the transactional outbox pattern in Spring Boot with Postgres

Pattern explainer, with reading list from this week's search results

The dual-write problem: saving an order and publishing an event are two writes, and one can fail. The outbox fix is to save the event in the same database transaction, then have a relay publish it.

💡 Why it matters to you: It is the standard answer to "how do you keep the database and Kafka in sync", and a staple of microservice system design interviews.
Read deeper

In Spring Boot: write the order and an outbox row in one @Transactional method. A scheduled poller (or Debezium reading the Postgres log) reads unpublished rows, sends them to Kafka or RabbitMQ and marks them published. Consumers must be idempotent because delivery is at least once.

Reading: the InfoQ piece on saga orchestration with the outbox pattern and a Spring Boot plus Debezium walkthrough from dev.to (both surfaced in this week's searches).

@Transactional
public void placeOrder(Order o) {
  orders.save(o);
  outbox.save(new OutboxEvent("order.created", json(o)));  // same transaction
}

@Scheduled(fixedDelay = 1000)
void relay() {
  for (OutboxEvent e : outbox.findUnpublished()) {
    kafka.send(e.topic(), e.payload());   // at-least-once
    e.markPublished();
  }
}
