Spring Boot 3.5 to 4.0 cheat sheet: renamed starters, Jackson 3 and the test annotations that changed

Spring Boot wiki: 4.0 Migration Guide · reference doc (checked Nov 19, 2026)

With Boot 4.2 still at RC2, the 4.0 migration guide is the document most 3.x projects need. Key points: spring-boot-starter-web becomes spring-boot-starter-webmvc, Jackson moves to tools.jackson, and @MockBean and @SpyBean are removed.

💡 Why it matters to you: You are on Spring Boot 3.x; this is the list of find-and-replace steps you will hit, and a good outline for a migration tutorial video.
Read deeper

Prerequisites: upgrade to the latest 3.5.x first and clear deprecation warnings. Boot 4 needs Java 17+ (21+ recommended), Servlet 6.1 and Spring Framework 7.x. Removed: Undertow, embedded executable launch scripts, Spock integration, and Spring Session Hazelcast and MongoDB support.

Jackson 3: group IDs and packages move from com.fasterxml.jackson to tools.jackson (jackson-annotations is the exception). @JsonComponent becomes @JacksonComponent, and you must define a JsonMapper bean, since an ObjectMapper bean is no longer enough. spring.jackson.use-jackson2-defaults eases the transition, and spring-boot-jackson2 is a deprecated compatibility module.

Testing: @MockBean and @SpyBean give way to @MockitoBean and @MockitoSpyBean. @SpringBootTest no longer provides MockMvc, so add @AutoConfigureMockMvc, and TestRestTemplate needs @AutoConfigureTestRestTemplate plus the spring-boot-resttestclient dependency (RestTestClient is the suggested replacement). Temporary escape hatch: spring-boot-starter-classic and spring-boot-starter-test-classic restore the full classpath.

Other renames worth grepping for: spring.data.mongodb.* connection properties move to spring.mongodb.*, spring.session.redis.* becomes spring.session.data.redis.*, and hibernate-jpamodelgen is replaced by hibernate-processor. Spring Batch now defaults to in-memory metadata; use spring-boot-starter-batch-jdbc to keep database-backed mode. Liveness and readiness probes are enabled by default.

<!-- before -->
<artifactId>spring-boot-starter-web</artifactId>
<!-- after -->
<artifactId>spring-boot-starter-webmvc</artifactId>

// before
@MockBean PaymentClient client;
// after
@MockitoBean PaymentClient client;

springdoc-openapi 3.2.0 and 2.10.0: required-property fixes, Java nullability and MCP tool registration

springdoc-openapi GitHub releases · Oct 24, 2026 (3.2.0 and 2.10.0), Sep 6 (3.1.1)

springdoc-openapi 3.2.0 targets the Spring Boot 4.1 line and 2.10.0 targets 3.5.x. Both mark PagedModel / PageMetadata and MonetaryAmount properties as required, upgrade Scalar to 0.6.83, and add opt-in Java nullability support and polymorphic oneOf as reusable components.

💡 Why it matters to you: This is your Swagger UI library; the required flags change generated clients, so regenerate any TypeScript API client for your React app after upgrading.
Read deeper

3.2.0 also shows the default API version only on operations that serve it, which fixes an HTTP 500 with @Schema(allowableValues), and can register MCP tools with a McpStatelessSyncServer. The 2.10.0 line adds ParameterCustomizer support for type-use annotations.

The earlier 3.1.1 (Sep 6) was security-focused: MCP and the dashboard are now opt-in, Scalar starters no longer register forwarded-header handling (set server.forward-headers-strategy behind a trusted proxy), a bounded per-locale OpenAPI cache was added (springdoc.cache.max-entries, default 100), and swagger-ui 5.32.14 addresses a DOMPurify XSS (CVE-2026-75838).

Express 5.3.0 upgrades qs, proxy-addr and body-parser after a fail-open limit option

Express 5.3.0 bumps qs (several CVEs), proxy-addr (CVE-2026-90711) and body-parser, whose limit option could fail open and allow oversized payloads. It also fixes res.send() adding Content-Length when Transfer-Encoding is present.

More npm advisories on MCP and install tooling: mssql-mcp-core SQL injection and unverified native downloads

GitHub Advisory Database (npm) · Nov 18-19, 2026

New High advisories: SQL injection in mssql-mcp-core write tools via unparameterized table names and WHERE clauses (CVE-2026-63129, Nov 19), install-artifact-from-github loading downloaded native artifacts without integrity verification (CVE-2026-73864, Nov 18), and command injection in augment-vir grep() (CVE-2026-63496).

💡 Why it matters to you: Many MCP servers are thin wrappers over a database or a shell; the pattern here is string concatenation, which you should avoid in your own Java and Node tools.
Read deeper

The mssql-mcp-core entry (GHSA-2m9m-6cr5-9x25) says table names and WHERE clauses were not parameterized in write tools, so a prompt-injected agent could shape SQL. Yesterday's code-review-mcp-server command injection fits the same pattern.

Fix for your own code: allow-list identifiers such as table names, bind values with parameters, and run MCP servers with a database role that can only do what the tool needs.

// parameterize values, allow-list identifiers
String sql = "SELECT * FROM " + allowedTables.require(table) + " WHERE id = ?";
jdbcTemplate.queryForList(sql, id);

rabbitmq/rabbitmq-server releases · Nov 16, 2026

RabbitMQ 4.4.1 and 4.3.8 are maintenance releases. 4.4.1 requires Erlang 27 or newer, requires application/json on HTTP API endpoints that take JSON bodies, and refuses HTTP publishing while a resource alarm is in effect.

💡 Why it matters to you: If your Spring services use RabbitMQ, this is the broker-side hardening and upgrade path to know before you move to 4.4.
Read deeper

4.4.0 (Oct 19) is the feature release: quorum queues support delayed messages via x-opt-delivery-time, plus x-name-prefix for server-named queues and Unix domain socket listeners. 4.3.8 fixes a startup failure with management.ssl.ip and requires the administrator tag for several runtime parameter endpoints; the polling consumer endpoint is capped at 1000 messages and 64 MiB by default.

Docker Compose 5.8.0 adds a top-level jobs element for scheduled and one-shot work

docker/compose releases · Nov 17, 2026

Compose 5.8.0 introduces a top-level jobs: element for one-shot units of work that run on demand or on a schedule. Scheduling requires Docker Engine 29.10 or later with the jobs extension enabled, while manual jobs work on any engine.

💡 Why it matters to you: It gives you a built-in way to run database backups, cleanup scripts or nightly eval runs next to your Spring Boot and Postgres services.
Read deeper

docker compose up registers scheduled jobs with the engine and down removes them. docker compose run <job> triggers a job immediately and returns its exit code. Compose 5.7.2 the same day fixed up --wait streaming logs and down -v keeping volumes that other services still use.

The jobs extension in Engine 29.10 was covered earlier as experimental, so treat scheduling as early-stage and keep cron as the fallback.

# compose.yaml sketch (exact job fields: see the release notes)
jobs:
  nightly-backup:
    # schedule and command defined per the 5.8.0 docs

# run one now
docker compose run nightly-backup
