Anthropic SDK errors now carry a code, and each code gets its own exception class

Claude Platform release notes · Nov 4, 2026 (older)

Every API error now includes an error code, a message and details. Each code maps to its own exception class in the SDKs (a constant in Go). Anthropic asks you to update to the latest SDK to use them.

💡 Why it matters to you: Catching a specific exception for overloaded or rate-limited calls beats parsing error strings, and it is how you build clean retry and fallback logic in a Spring service.
Read deeper

This is an older note, but it matters because retry logic is where most LLM apps are fragile. A typed exception lets you retry on a transient code, fail fast on an invalid request and alert on an auth problem, each in its own catch block.

The notes link a Handle errors page. Check which SDK version added your language's classes before relying on them.

try {
    client.messages().create(params);
} catch (RuntimeException e) {
    // Catch the specific exception class for the error code,
    // retry the transient ones and fail fast on the rest.
}

Local models and inference

vLLM 0.34.0: Model Runner V1 is gone and the KV cache sizes itself by default

vLLM GitHub releases · Nov 18, 2026

vLLM 0.34.0 packs 1,061 commits from 412 contributors and 10 new models, including Mistral Large 4, MiniMax-M3.1-Flash and Nemotron-3.5-Transcribe. The extensible KV cache is now on by default and is sized from memory actually free after warmup, and Model Runner V2 is the only GPU runner.

💡 Why it matters to you: If you serve an open model for a RAG or agent project, you may be able to drop gpu_memory_utilization from your config, but the new default block size of 64 can change behaviour for short shared prefixes.
Read deeper

Breaking changes in the release notes: the default block size is 64, ROCm 7.2 images are dropped and huggingface_hub 2.0.0 or later is required. A search summary adds that setting VLLM_USE_V2_MODEL_RUNNER=0 now fails at startup and that custom logits processors must move to the V2 sampler module.

The release notes also claim speedups on Blackwell and MI355X, including up to 1.95x decode on Step5 (GB200). Those are vendor-style numbers on hardware most of us do not own, so benchmark your own workload.

Spring AI and the JVM

Spring AI 2.1 Decision Models: a probability, not a prose answer, and where the guardrails sit

Spring blog · Nov 26, 2026

Christian Tsolov's post introduces DecisionModel, an API for tasks with a fixed set of outcomes. It returns typed answers with probabilities through YesNoQuestion, ChoiceQuestion and ScoreQuestion. The article reports a median latency of 29 ms for three questions on a local Ollama model and about 150 ms on a hosted one.

💡 Why it matters to you: Routing, classification and moderation do not need a frontier chat model. A probability you can threshold is cheaper, faster and easier to test than parsing free text.
Read deeper

The post's main point is that the probability matters more than the boolean: for example, 0.9 or higher triggers an automatic action while 0.4 to 0.9 goes to a person. DecisionGuardrailAdvisor screens input and output with outcomes PASS, REVIEW, BLOCK or SUPPORT, and DecisionJudge scores several criteria in one call.

Caveats from the article: thresholds are model-specific, a local model left a self-harm message at REVIEW where the hosted one escalated it, and by default the guardrail does not screen tool-call arguments or tool results. The community extension is at 0.5.0, its first release.

DecisionResponse r = decisionModel.call(DecisionPrompt.builder()
    .text("My headphones arrived, but the left side does not work.")
    .question("defect", YesNoQuestion.builder()
        .text("Does the customer report a defect?").build())
    .build());
double p = r.getYesNo("defect").getProbability();

MCP and protocols

MCP Java SDK 2.2.0 adds a stateless server and client for the 2026-07-28 spec

MCP Java SDK GitHub releases · Nov 16, 2026

The Java SDK 2.2.0 adds a stateless server and client for the 2026-07-28 MCP spec in the io.modelcontextprotocol.modern package, leaving the legacy client and server untouched. The roots, sampling and logging initiation APIs are deprecated, per SEP-2577.

💡 Why it matters to you: Stateless means no sessions, so an MCP server in front of your Spring Boot service can scale behind a plain load balancer without sticky routing.
Read deeper

Breaking changes: McpTransportContext no longer uses content-based equality, and several preview APIs changed, including McpParamHeaders becoming McpHeaders. The release also enforces required client capabilities and validates Mcp-Param headers.

Milestone 1 in October passed 37 required conformance scenarios and described the design as one server for sync or async use with developer-supplied tool, resource and prompt catalogs.

Paper explained: "Think with Skills" turns skill descriptions into pseudocode plans, 35.0% to 62.0% on SkillsBench

arXiv 2611.02830 · Nov 2026

Boshen Zhou and co-authors train reasoning models to turn natural-language skill descriptions into task-specific pseudocode plans before execution. The pseudocode records operations, conditions, intermediate results and dependencies. Training combines supervised fine-tuning with Group Relative Policy Optimization, and success on SkillsBench rises from 35.0% to 62.0%.

💡 Why it matters to you: Agent skills are plain markdown today, and ambiguity in them is a common failure. Asking the agent to write a plan with explicit conditions first is a prompt pattern you can try now.
Read deeper

The abstract comes from a third-party mirror, and I did not open arXiv itself. The pseudocode is a plan for the model to follow, not code sent to an external interpreter.

To try the idea without training: add a step to your skill-driven agent that says, before acting, write numbered pseudocode for this task with conditions and dependencies, then follow it.

Paper pick: TokenPilot keeps the prompt cache warm and cuts long-session agent cost by 56 to 87% (older)

arXiv 2606.17016 · Jun 16, 2026

TokenPilot argues that text pruning and memory eviction change the prompt layout and break cache prefixes, costing more than they save. Its Ingestion-Aware Compaction stabilises prefixes before content enters the context, and Lifecycle-Aware Eviction removes segments only once their relevance expires. On PinchBench and Claw-Eval it reports cost cuts of 61% and 56% in isolated mode and 61% and 87% in continuous mode.

💡 Why it matters to you: If you use prompt caching on Claude or OpenAI, the way you trim history decides whether you keep the discount.
Read deeper

This is a June paper, included because cache-aware context management is a live cost lever. The figures come from the paper's abstract as shown in search, and I did not check the full text.

Rule of thumb from the idea: append to context, do not rewrite earlier turns, and trim in batches so the cached prefix survives.
