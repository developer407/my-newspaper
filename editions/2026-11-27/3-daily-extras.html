Tool: Deep Agents Code, a terminal coding agent that works with any LLM

langchain-ai/deepagents on GitHub · read Nov 27, 2026 (deepagents-code 0.2.15 on Nov 26)

Deep Agents Code is the pre-built terminal coding agent in the Deep Agents harness, positioned like Claude Code or Cursor but model-agnostic. The harness gives it sub-agents with isolated context, a filesystem, sandboxed shell, persistent memory, human-in-the-loop approval, skills and MCP tools. Version 0.2.15 flags partial cost totals in the status bar.

💡 Why it matters to you: You can point it at Claude, a local Ollama model or another provider and compare the same task across them, which makes a good side-by-side video.
Read deeper

The repository shows about 31.6k stars. The README only documents installation for the CLI and points to the docs for the rest, so I have not verified day-to-day behaviour.

Release 0.2.15 also starts refreshing the price catalogue when a turn begins and replaces Baseten models retiring on Dec 18 in its model recommendations.

curl -LsSf https://langch.in/dcode | bash   # install command from the README

Tool: Meta's Omnilingual ASR speech models arrive in Transformers 5.24 for 1,600+ languages

Hugging Face Transformers release notes · Nov 21, 2026

Transformers 5.24.0 adds Omnilingual ASR, Meta FAIR's multilingual speech recognition models covering more than 1,600 languages. The same release adds Sarvam AI's SarvamMLA and SarvamMoE architectures for its 105B and 30B models, plus Inkling 2 Mini and Apertus 1.5.

💡 Why it matters to you: Indian-language captions for your tutorials and voice features for apps are now a pipeline call away, though quality per language needs testing.
Read deeper

Breaking changes in 5.24: past_key_values and cache_params are renamed to cache (old names still work with a deprecation warning), peft 0.22.0 or later is required and modeling_attn_mask_utils.py is removed. 5.24.1 on Nov 24 restored backward compatibility for the cache rename in remote code.

I did not verify per-language accuracy or the exact model IDs, so read the model card on Hugging Face before promising results.

pip install -U 'transformers>=5.24.1'
# then load the Omnilingual ASR model id from its Hugging Face model card

GitHub repos of the day

Repo: embabel/embabel-agent, a JVM agent framework with planning (about 4.6k stars)

GitHub repository page · read Nov 27, 2026

Embabel is an agent framework for the JVM, written in Kotlin and usable from Java. It plans with Goal Oriented Action Planning by default, with a pluggable planner and Utility AI as an option. Agents use @Agent, @Action, @Goal and @Condition annotations and integrate with Spring.

💡 Why it matters to you: It is the most Spring-flavoured agent framework, with MCP client and server support, A2A, OpenTelemetry tracing and Ollama, OpenAI and Anthropic models.
Read deeper

Its strongest idea is typed domain objects with planning instead of a free-form loop, which makes agents more testable with mocks and a fake operation context. The README's quick start is a Maven starter at version 0.3.0, while release notes elsewhere show 1.5.x versions, so check which is current.

Run the OPENAI_API_KEY example first, then swap in a local Ollama model.

<dependency>
  <groupId>com.embabel.agent</groupId>
  <artifactId>embabel-agent-starter</artifactId>
  <version>0.3.0</version>
</dependency>
  • Original: embabel/embabel-agent
  • Related: Embabel releases

Repo: langchain4j/langchain4j, the Java-native LLM library (about 13.4k stars)

GitHub repository page · read Nov 27, 2026

LangChain4j describes itself as built for Java, not ported to it. It offers one API across 20+ LLM providers and 30+ embedding and vector stores, tool calling with MCP support, agents and RAG, with Quarkus, Spring Boot, Helidon and Micronaut integrations.

💡 Why it matters to you: It is the best comparison point for Spring AI. Build the same RAG demo in both and you have a ready-made tutorial.
Read deeper

Providers listed include OpenAI, Anthropic, Google Gemini and Vertex AI, Ollama, Hugging Face and Mistral. Vector stores include pgvector, Pinecone, Milvus and Chroma.

The repository has 2.7k forks. Recent releases are tagged almost daily, so pin a version.

git clone https://github.com/langchain4j/langchain4j-examples

Repo: JetBrains/koog, a Kotlin and Java agent framework with graph workflows (about 4.7k stars)

GitHub repository page · read Nov 27, 2026

Koog is JetBrains' framework for building and running AI agents in Kotlin, with a Java-usable API. It targets JVM, JS, WasmJS, Android and iOS, and adds retries, state restoration, history compression, OpenTelemetry exporters, MCP and ACP support, streaming, parallel tool calls and graph-based workflows. It requires JDK 17 or higher.

💡 Why it matters to you: It integrates with Spring Boot and Ktor, and its history compression and state restoration speak to the two problems that hurt long-running agents.
Read deeper

The README quick start is Kotlin only, with an AIAgent that takes a prompt executor, system prompt and model. For Maven you add the koog-agents-jvm artifact.

Release 1.3.0 in September added ready-made model definitions for many providers, so the project is active.

val agent = AIAgent(
    promptExecutor = MultiLLMPromptExecutor(OpenAILLMClient(apiKey)),
    systemPrompt = "You are a helpful assistant.",
    llmModel = OpenAIModels.Chat.GPT4o
)

Project ideas of the day

Idea: a support-ticket triage service with probabilities and a React review queue

Idea inspired by the Spring AI 2.1 Decision Models post

Build a Spring Boot service that classifies incoming messages with a DecisionModel (defect, refund, urgent), acts automatically above one probability, and sends the 0.4 to 0.9 band to a React review queue with the probability shown.

💡 Why it matters to you: It teaches the most employable AI habit: treat model output as a score with thresholds and human review, not as truth.
Read deeper

Steps: run the local Ollama decision model first, add a table that stores every decision and its probability, then add a React page that lets a reviewer correct labels. Use the corrections to tune thresholds.

For a tutorial, the interesting episode is comparing a local model with a hosted one on the same 50 messages, as the Spring post warns thresholds differ between models.

  • Reference: Decision Models in Spring AI 2.1
  • Related: Spring AI reference

Idea: a RAG quality lab that compares BM25, vectors and a small reranker on your own questions

Idea inspired by Qdrant 1.20 and the reranker benchmarks

Index the Spring Boot docs into Qdrant, add 30 hand-written questions with expected source pages, and score keyword, vector and hybrid retrieval, with and without a 149M-parameter reranker, on hit rate and latency.

💡 Why it matters to you: It turns a vague claim that hybrid search is better into a number you can show on screen, and it gives you an eval story for interviews.
Read deeper

Steps: chunk the docs, store vectors and a full-text payload index in Qdrant 1.20, query three ways, then rerank the top 20. Plot hit-at-5 against latency in a small React chart.

Keep the question set in a file, so every run is comparable. Report where the reranker helped and where it did nothing.

  • Reference: Qdrant releases
  • Related: RAGe evaluation framework

Idea: a RestTemplate-to-RestClient migration checker with a before-and-after video

Idea inspired by the Spring Boot 4.2 deprecations

Spring Boot 4.2 deprecates RestTemplateBuilder and the related auto-configuration in favour of RestClient.Builder, and deprecates TestRestTemplate in favour of RestTestClient. Write a small tool that scans a codebase for these types and prints the replacement for each.

💡 Why it matters to you: Every Boot team has this migration ahead of it, so a clear tutorial plus a free tool is easy to find and share.
Read deeper

Start with a regex scan for RestTemplate, RestTemplateBuilder and TestRestTemplate, then add a Spring AI step that proposes a rewritten snippet for each hit. Show a diff, and let the developer accept it.

Test it on an old open-source Spring project and record the before and after.

grep -rln 'RestTemplate\|TestRestTemplate' src/
  • Reference: Spring Boot 4.2 release notes
  • Related: Spring RestClient docs

Learn today: stand up a stateless MCP server with the Java SDK's modern package

MCP Java SDK 2.2.0 release notes · Nov 16, 2026

The 2.2.0 SDK adds a stateless server and client for the 2026-07-28 spec in the io.modelcontextprotocol.modern package. Spend 30 minutes building one tool, such as a lookup over your course catalogue, and call it from a client.

💡 Why it matters to you: Stateless MCP removes sessions, which changes how you deploy: any instance can answer any request.
Read deeper

Plan: create a Spring Boot project, add the mcp dependency at 2.2.0, register one tool in the modern server and start it. Then run MCP Inspector against it to confirm the tool list and a call.

Compare with the legacy server in the same SDK, which is unchanged. Note what you no longer need to store between requests.

npx @modelcontextprotocol/inspector   # then connect to your server's URL
