Spring Data JPA 4.2.0: startup validation for @Query projections and a cheaper HQL parser

Spring Data JPA GitHub releases · Nov 20, 2026

Spring Data JPA 4.2.0 disables the second-level cache during AOT metamodel bootstrap, validates @Query methods at startup using static projections and reduces HQL parser cold-start allocations. It upgrades to Hibernate 7.4.15.Final.

💡 Why it matters to you: A repository method with a bad projection now fails when the app starts, not when a user hits the endpoint, which is exactly where you want JPA mistakes to surface.
Read deeper

Bug fixes include correct null handling in backward keyset scrolling, support for the % modulo operator in HQL, and applying Sort only to the outermost query in parenthesised HQL set operations. AOT code generation is fixed for derived delete queries returning Set.

Patch lines 4.1.3 and 4.0.9 shipped the same day with the keyset and query fixes and no new features, so you can take the fix without taking the feature release.

@Query("select new com.acme.UserSummary(u.id, u.name) from User u where u.active = true")
List<UserSummary> findActive();
// 4.2 validates this projection at startup

Spring Framework 7.0.11 fixes 13 CVEs across data binding, WebSocket and STOMP, and SpEL

Spring Framework GitHub release · Nov 26, 2026

The maintenance release closes 13 CVEs, including data-binding on indexed types (CVE-2026-59374), multipart part smuggling (59389), missing Origin validation when WebSocket handling is configured directly (59390), STOMP message smuggling and disclosure (59391, 59392), an open redirect in UrlHandlerFilter (59394) and unintended constructor and method invocation through SpEL type conversion (59430).

💡 Why it matters to you: Any Spring Boot app with WebSocket, file upload or SpEL on user input should take 7.0.11 or the matching Boot patch release.
Read deeper

Several of the rest are denial-of-service issues: parameter-based content negotiation (59398), streaming text decoding in WebFlux (59418), HTTP client observations (59419), PathPattern (59429) and SpEL collection selection (59431). maxInMemorySize was also bypassed in Jaxb2Decoder (59393).

Check the Spring Security advisories for the exact fixed versions on your 6.x, 7.0 and 7.1 lines, and confirm which Boot version pulls in the patched Framework.

# see which Framework version Boot resolves
./mvnw dependency:tree -Dincludes=org.springframework:spring-core
