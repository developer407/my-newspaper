Spring Boot 4.2.0 is out, with 4.1.3 and 4.0.10 patches the same day

spring-projects/spring-boot releases · Nov 19, 2026

Spring Boot 4.2.0 went GA on Nov 19. It refines forwarded-header support, deprecates Apache Pulsar support (Spring for Apache Pulsar moved to the ASF), and pulls in Spring Framework 7.1.0, Spring Security 7.2.0, Hibernate 7.4.15, Jetty 12.1.15 and Micrometer 1.18.0. The 4.1.3 and 4.0.10 patch releases are bug-fix only.

💡 Why it matters to you: This is the upgrade you have been waiting on after the 3.5 to 4.0 migration; the GA unlocks Spring AI 2.1 (which builds on Boot 4.2) and Spring Cloud 2026.0.

Spring Batch 6.1 GA: @JobParameter, PageableItemReader and big restart and partitioning speedups

Spring blog · Nov 19, 2026

Spring Batch 6.1 adds a @JobParameter annotation that replaces @Value("#{jobParameters[...]}") SpEL, a type-safe PageableItemReader for Spring Data repositories, JSON Lines writing, and a collection prefix for MongoDB job repositories. Restarts only check the last job execution, and JdbcJobExecutionDao#findJobExecutions drops from 1 + 3N queries to 2.

💡 Why it matters to you: If you run scheduled imports or report jobs behind your Boot apps, the query cut and the typed parameter injection are immediate quality-of-life wins.
Read deeper

Partitioned steps get a new JobRepository#countRunningStepExecutions instead of loading every worker's execution; one reported case saw about 10x lower memory on the polling node. The async classes AsyncItemProcessor, AsyncItemWriter and ChunkTaskExecutorItemWriter moved to spring-batch-core.

Breaking changes: staged builder DSL return types changed (source and binary incompatible), Avro reflection needs explicitly trusted item types, the no-arg JDBC DAO constructors were removed and JsonLineMapper's raw type changed. Apache Derby support is deprecated. It builds on Spring Framework 7.1.0, Spring Integration 7.2.0, Spring Data 2026.1.0 and Micrometer 1.18.0.

Two MCP servers fall to browser DNS rebinding: Jupyter MCP (CVSS 9.3) and Todoist MCP

GitHub Advisory Database · listed Nov 19-20, 2026 (Jupyter advisory originally published Jul 12)

CVE-2026-77359 affects jupyter-mcp-server 1.0.2 and earlier: in streamable-http mode, /mcp rejects forged Host and Origin headers but custom management routes /api/connect and /api/stop do not, so a malicious website can rebind DNS and stop the kernel or point the server at attacker-controlled Jupyter URLs and tokens. Fixed in 1.0.3. CVE-2026-76807 is the same pattern in @doist/todoist-mcp, letting websites write and delete Todoist data through the local server.

💡 Why it matters to you: Any local MCP server you build or demo, including Spring AI ones on localhost, has this exposure unless you validate Host and Origin on every route.
Read deeper

The advisory's guidance: enforce Host and Origin validation on all custom routes before parsing bodies or changing state, require a bearer token (MCP_TOKEN) on state-changing routes, and bind standalone HTTP to 127.0.0.1 with an explicit allowlist for anything else.

In Spring this is a filter or security rule that rejects requests whose Host is not in an allowlist; do not rely on being on localhost.

@Bean
FilterRegistrationBean<OncePerRequestFilter> hostGuard() {
    OncePerRequestFilter f = new OncePerRequestFilter() {
        protected void doFilterInternal(HttpServletRequest req, HttpServletResponse res, FilterChain c)
                throws ServletException, IOException {
            if (!Set.of("localhost:8080", "127.0.0.1:8080").contains(req.getHeader("Host"))) {
                res.sendError(421); return;
            }
            c.doFilter(req, res);
        }
    };
    return new FilterRegistrationBean<>(f);
}

CodeWhale CVE-2026-83816: a "read-only" allowlist let fd, rg and git grep run arbitrary programs

GitHub Advisory Database · Nov 19, 2026

CodeWhale (also called DeepSeek-TUI), versions 0.8.67 and earlier, auto-approved fd, rg and git grep as read-only even though flags like fd -x, rg --pre and git grep --open-files-in-pager execute external programs with no shell metacharacters. A prompt injection in a repo file, issue or web page could make the agent run attacker code without an approval prompt. CVSS 3.1 8.1 (High), fixed in 0.9.0. A second advisory (CVE-2026-83817) covers automation auto_approve defaulting to true.

💡 Why it matters to you: If you build an agent with a shell tool, a read-only allowlist is only as safe as every flag of every command on it.
Read deeper

The advisory's suggested mitigations: remove fd, rg and git grep from the read-only list, or reject their exec-capable flags. A better pattern is to allowlist full argument shapes, not command names, and to run commands in a sandbox.

This is the same lesson as Claude Code's hardened permissions and Gemini CLI skipping insecure MCP servers: command-prefix rules are easy to get wrong.

OpenAPI code generators as an attack path: Refitter, Jane and Tapir advisories rated critical or high

GitHub Advisory Database · Nov 19-20, 2026 (several originally published earlier)

JWT library lessons from pac4j-jwt CVE-2026-29000 (CVSS 10) and friends: never let the token pick the algorithm

Search-result summaries of CVE advisories (CIS, Snyk, SentinelOne) · 2026 · deep-dive, dates vary

Several 2026 JWT bugs share one root cause: the library lets the token's own header influence how it is verified. pac4j-jwt CVE-2026-29000 (CVSS 10.0) lets an attacker with only the server's public RSA key forge tokens with arbitrary claims, fixed in 4.5.9, 5.7.9 and 6.3.3. PyJWT CVE-2026-48526 allows the issuer's public key to be used as an HMAC secret, and authlib CVE-2026-27962 has a JWK header injection flaw.

💡 Why it matters to you: You use jjwt and Spring Security JWTs, so pin the algorithm and key on the server and prefer Spring's resource-server support over hand-rolled filters.
Read deeper

Best-practice summary from the same sources: pin the verification algorithm (never trust none or the header's alg), keep sensitive data out of the payload, store tokens in httpOnly cookies rather than localStorage, require PKCE for all OAuth clients with exact redirect-URI matching, and rotate refresh tokens with family invalidation. Passkeys solve phishing but not account recovery.

These are summaries from secondary sources; confirm versions and severities in the CVE records before quoting them.
