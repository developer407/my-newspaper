Node / MERN & Python backends

NestJS 12.5.0 adds payload limits everywhere — and lowers WebSocket and TCP defaults

nestjs/nest · v12.5.0 and v11.2.10, Nov 12, 2026

NestJS 12.5.0 adds limits to transports and adapters: maxPayload for WsAdapter, maxWaitingMessages for IoAdapter, maxConcurrentMessages for TCP, maxPendingResponses for gRPC, maxMessageSize for RabbitMQ and jsonFieldsSize for Fastify multipart. The defaults got tighter: the WsAdapter payload limit drops from 100 MB to 1 MB, the TCP maxBufferSize default falls from 128 Mi to 16 Mi characters, and an unset TCP host now listens on localhost only.

💡 Why it matters to you: If you run Socket.IO or WebSocket features in a MERN project, large messages will start failing after the upgrade — set the limits deliberately.
Read deeper

Also: multipart requests default to 1,000 parts, a limit set to NaN now uses the default instead of disabling the limit, and guards/interceptors/pipes that can't run now fail at startup. The 11.2.10 backport tightens validation: buffers sent in place of validated classes are rejected and validation error messages are capped.

Update @nestjs/core and the platform packages together, as the release notes advise.

// microservice over TCP: bind explicitly, it is localhost-only by default now
const app = await NestFactory.createMicroservice(AppModule, {
  transport: Transport.TCP,
  options: { host: '0.0.0.0', port: 3001 },
});

Keycloak 26.8.2 fixes 33 issues, including a stored XSS on the login page and a SAML signature bypass

keycloak/keycloak · 26.8.2, Nov 5, 2026

Keycloak 26.8.2 upgrades Quarkus to 3.40.1.1 and lists 33 security fixes. Notable items: a stored XSS on the login page, an out-of-bounds write in the bundled Brotli decoder, account takeover via a stale SSO note in Organization identity-first login, and several SAML issues including a signature bypass via a percent-encoded parameter name.

💡 Why it matters to you: If Keycloak is your OAuth2/OIDC provider behind Spring Security resource servers, upgrading is non-optional — SAML and login-page issues sit on the unauthenticated surface.
Read deeper

26.8.1 (Oct 13) already fixed about 22 items: unsigned forged logout tokens accepted by OIDC broker back-channel logout when signature validation is disabled, a delegated admin with manage-users able to become realm-admin via group role mappings, and token exchange issuing an active bearer token without required mTLS binding.

26.8.0 (Oct 1) promoted OID4VCI to preview and moved parameterized scopes and token-exchange delegation 'for AI agents and automation' to preview — useful context for MCP authorization.
