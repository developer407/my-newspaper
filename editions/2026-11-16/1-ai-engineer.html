MCP & tool safety

MCP reference servers 2.4.0: six vulnerabilities fixed across the filesystem, git and fetch servers

modelcontextprotocol/servers · v2.4.0, Nov 11, 2026

The official MCP reference servers shipped 2.4.0 with security fixes for six vulnerabilities across three servers. Filesystem 2.3.0 keeps reads tied to the file that was checked and fixes move_file; git and fetch (2026.11.11) block command execution through repo config, tighten --repository confinement, block IPv6 site-local addresses and normalize robots.txt paths. The Everything server now binds HTTP transports to loopback by default.

💡 Why it matters to you: These are the servers most tutorials (and many Spring AI MCP demos) tell you to plug in first — if you copied one into a project or a video, bump it today.
Read deeper

This is the fourth security-flavoured release in a row: 2.1.0 (Oct 25) closed eight issues such as symlink-swap write races and IDNA host-check bugs, 2.2.0 (Oct 28) reacted to an October CA-certificate compromise and Node.js security releases, and 2.3.0 (Nov 4) added hardening options — a --read-only mode for filesystem, an operator host allowlist and configurable timeout for fetch, and git_merge/git_remote tools. 2.0.0 (Oct 19) moved the servers to the modern spec and requires Node 24 or later for the TypeScript ones.

Practical reading: treat every MCP server as code that runs with your user's permissions. Pin versions, prefer the read-only/allowlist modes where the server offers them, and keep HTTP transports on loopback unless you really need remote access. The git and fetch fixes are the classic indirect-prompt-injection surface: repository config and fetched pages are attacker-controlled text.

Spring AI & the JVM agent stack

The Spring AI community org is quietly becoming an agent platform: A2A, AgentCore, decision extensions, MCP security

github.com/spring-ai-community · repo activity Nov 12–15, 2026

Four repos moved in the last four days: spring-ai-agentcore (Boot integrations for Amazon Bedrock AgentCore, updated Nov 13), spring-ai-decision-extensions (model-as-a-judge, self-refine and guardrail advisors plus a chat-model adapter), mcp-security (Spring Security configuration for MCP, Nov 12) and spring-ai-a2a (agent servers over A2A). The old spring-ai-typesafe repo is archived — its functionality moved into Spring AI and the decision extensions.

💡 Why it matters to you: If you want to teach 'production agents on Spring', this is the shopping list: auth for MCP, agent-to-agent, hosted runtime, and LLM-as-judge guardrails — all Spring-native.
Read deeper

spring-ai-playground (local execution layer for agent tools with an MCP server, agentic chat and human-in-the-loop approval, 146★) and spring-ai-session (event-sourced conversation memory) round out the picture; the ACP harness client that drives coding agents like Goose and OpenCode was covered earlier this week.

None of these are GA Spring AI modules — they live in the community org, so expect version churn. They are good candidates for tutorials precisely because the docs are thin and your content fills the gap.

Agent frameworks, SDKs & gateways

DSPy 3.5.0 drops LiteLLM as a hard dependency — and changes prompts and defaults

stanfordnlp/dspy · 3.5.0, Nov 10, 2026

DSPy 3.5 makes LiteLLM and the OpenAI Python library optional by routing calls through a lighter in-house lm15 engine, cutting install size and import time. RLM, Flex and GEPA leave experimental status, ReActV2 becomes dspy.ReAct, XMLAdapter becomes the default adapter, and tools can return images and files.

💡 Why it matters to you: If you use DSPy to optimise RAG or agent prompts, the release notes themselves say to re-evaluate optimised programs — budget an eval run before upgrading.
Read deeper

The maintainers warn explicitly: 'This release changes prompts, defaults and APIs.' Other additions: RLM history save/reload, prewarmed interpreters, and restricted disk-cache loading by default (a security-motivated change). Earlier 3.4.0 (Sep 25) added a Jev integration through TypeSafe with experimental Choice/Score output types and ReAnchor, an optimiser that calibrates decision thresholds against your metric.

For a Java developer the lesson is portable: prompt optimisation is just search against a metric, and DSPy's GEPA/ReAnchor are worth reading even if you never run Python in production.

Ragas 0.4.4 patches CVE-2026-6587 — multimodal metrics could read internal URLs and local files

Research, explained simply

Two new arXiv agent papers: team topology + human intervention, and coding agents doing customer-facing engineering

arXiv 2611.12545 (Nov 9) and 2611.03551 (Nov 2) — seen via search listings; arxiv.org was not reachable

2611.12545 argues that most multi-agent frameworks bake team shape into the software and instead proposes making topology and the timing of human intervention configurable (a system description with testable hypotheses, no comparative results). 2611.03551 asks whether coding agents can do forward-deployed-engineer work — discovering customer requirements and turning them into deployment decisions — using enterprise text-to-SQL as the test case.

💡 Why it matters to you: Both map to design choices you make in LangGraph or Spring AI: who decides the graph shape, and where the human approval node goes.
Read deeper

I could only see the search-index summaries, not the full papers, so treat the descriptions as headlines. Related listings that surfaced in the same search: a paper on agents that do not learn from corrections across sessions, one on 'Knowing When to Intervene: Causal Evaluation of AI Agents', and 'Phantom Consensus', a multi-agent social-reasoning benchmark.

Reading tip: for each paper find the evaluation table first — if there isn't one (as in the topology paper) it's a position piece, not evidence.
