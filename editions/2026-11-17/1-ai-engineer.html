MCP Java SDK 2.2.0 goes GA: a stateless “modern” server and client for the 2026-07-28 spec

modelcontextprotocol/java-sdk · v2.2.0, Nov 16, 2026 (M2 on Nov 13)

The MCP Java SDK 2.2.0 is out of milestone status. It adds a stateless server and client for the 2026-07-28 MCP spec in a new io.modelcontextprotocol.modern package, while the legacy client and server stay unchanged. Roots, sampling and logging are deprecated, following SEP-2577.

💡 Why it matters to you: This is the SDK underneath Spring AI’s MCP support, so the “modern” server you will enable with spring.ai.mcp.server.protocol=MODERN in Spring AI 2.1 now sits on a GA library.
Read deeper

The release notes list breaking changes: McpTransportContext no longer uses content-based equality, and several APIs that were only in the modern preview changed. It also carries Streamable HTTP and SSE bug fixes plus dependency bumps (Reactor, Jackson, JSpecify). The M2 build on Nov 13 had already added enforcement of required client capabilities and validation of Mcp-Param headers.

Practical read: if you built an MCP server with the 2.1.x SDK, nothing forces a move. If you want the no-session, horizontally scalable model, start a spike on the modern package and watch the deprecations of roots, sampling and logging, because Spring AI’s RC2 notes say those have no modern equivalent yet.

# application.properties (Spring AI 2.1.0-RC2, from the release notes)
spring.ai.mcp.server.protocol=MODERN

Spring AI 2.1.0-RC2 upgrade checklist: temperature is gone for Anthropic, token counts go up

spring.io blog · Spring AI 2.1.0-RC2, Nov 9, 2026

Beyond the new APIs, the RC2 notes carry changes that can break a working app. The Anthropic SDK now defaults to API version 2026-10-21, which rejects temperature, topP and topK: Spring AI discards any values and logs a WARN. Prompt token counts for Anthropic and Bedrock Converse now include cached read and write tokens, so reported usage rises.

💡 Why it matters to you: If your Spring AI demo sets temperature on a Claude model, it will quietly stop doing anything; and any cost dashboard you built from usage metrics will jump after the upgrade.
Read deeper

Other items to check: API keys for Anthropic are now sent as Authorization: Bearer; Typesense’s embedding-dimension no longer defaults to 1536 and initialisation fails if reading the collection fails for reasons other than “not found”; custom ChatModel implementations must emit the complete ToolCallPart at the same index as partial parts; and DeepSeek streaming goes through DeepSeekApi.chatCompletionStreamRaw.

The MCP “modern” server is sync-only for now (type=ASYNC fails at startup). Remove any manual cache-token adjustments you wrote, or you will double count.

# before (now ignored, WARN logged)
spring.ai.anthropic.chat.options.temperature=0.2

# after: remove it; also remove manual cache-token fixes in your metrics code

“Durable execution” for agents: Temporal’s Cornelia Davis on A Bootiful Podcast

spring.io · A Bootiful Podcast, Nov 5, 2026 (12 days old, kept for the topic)

Josh Long revisits a 2018 conversation with Cornelia Davis, now at Temporal. They cover durable execution (workflows that resume after failures or long waits), human-in-the-loop patterns, event sourcing and why Temporal fits agentic applications, including a Temporal Agent Harness with typed tools and policy-based approvals.

💡 Why it matters to you: Long-running agent runs (waiting for a human approval, retrying a flaky tool) are exactly where a plain Spring Boot request cycle breaks down; durable execution is the pattern to learn before agents hit production.
Read deeper

The post says little about Spring specifically, so treat it as a concept briefing. It pairs well with two things already in the ecosystem: Spring AI’s new Session Memory (an event log with turn-aware compaction, introduced in 2.1.0-RC1) and Pydantic AI’s 2.68 release, which can run sub-agent delegations as Temporal or DBOS child workflows.

Content idea: “what happens to my agent when the pod restarts?” is a good tutorial hook, because most demos silently lose state.

Anthropic Python SDK 2.7–2.9: Fable 5.2 and Mythos 5.2 land, and seven beta headers are on the way out

anthropics/anthropic-sdk-python · v2.7.0 (Nov 9), v2.8.0 (Nov 10), v2.9.0 (Nov 16)

v2.7.0 added the claude-fable-5-2 and claude-mythos-5-2 models. v2.9.0 warns that several beta header values are deprecated and will be removed later, including prompt-caching-2024-07-31, pdfs-2024-09-25 and token-counting-2024-11-01; the API still accepts them. 💡 Why it matters to you: Any Claude integration you wrote in 2025 probably still sends these headers. Clean them out now, in your Python scripts and (by analogy) in the Java SDK config behind Spring AI.
Read deeper

Two headers need care: files-api-2025-04-14 and skills-2025-10-02 change response shapes, so the release notes tell you to follow the migration guides before removing them. v2.8.0 hardened Bedrock and Vertex clients: a ; in a Bedrock model ID is sent as-is, empty model, project or region values now raise errors on Vertex, and IDs are percent-encoded in Google Cloud paths.

v2.6.0 (Nov 5) also stopped recording sampling parameters on OpenTelemetry spans, which matters if you ship traces to a shared backend.

Plannotator: review and annotate your coding agent’s plans before it writes code

backnotprop/plannotator · trending, Nov 16, 2026 (≈12.6k stars, Apache-2.0 or MIT)

It also reviews diffs and pull requests and works with Claude Code, Codex, Copilot CLI, Gemini CLI, OpenCode and others.

💡 Why it matters to you: Plan review is the cheapest quality gate in an agent workflow: catching a bad plan costs seconds, catching a bad diff costs an hour.
Read deeper

Install is a one-line script, then in Claude Code /plugin marketplace add backnotprop/plannotator. Commands include /plannotator-last, /plannotator-review and /plannotator-annotate. As with any curl | bash installer, read the script first.

/plugin marketplace add backnotprop/plannotator
/plugin install plannotator@plannotator
