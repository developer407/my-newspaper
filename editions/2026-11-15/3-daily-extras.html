Open WebUI 0.13: coding agents as models, Tether companion app and Auto tool-permission mode

open-webui/open-webui · Nov 8, 2026

Open WebUI 0.13.1 lets agents such as Claude Code, Codex and Pi appear in the model picker on Open Terminals that offer them, adds a desktop companion app called Tether, keeps a stable prompt start for tool chats (better provider prompt caching) and adds an Auto mode, off by default, where a review model decides whether a tool call needs approval.

💡 Why it matters to you: A self-hosted chat UI in front of Ollama or any OpenAI-compatible API is the fastest way to demo local models to clients — and Auto mode is a neat pattern to copy.

ag-ui-protocol/ag-ui — the Agent-User Interaction Protocol (17.4k★, MIT)

GitHub · maintained with CopilotKit

AG-UI is an open, lightweight, event-based protocol that standardises how agent back-ends talk to user-facing apps. Back-ends emit about 16 standard event types over SSE, WebSockets or webhooks; integrations cover LangChain, CrewAI, Mastra, Google ADK, Pydantic AI and more, with SDKs including Java and Kotlin.

💡 Why it matters to you: MCP gives agents tools; AG-UI gives them a UI — a clean way to stream your Spring AI or LangGraph agent's steps into a React front end.
Read deeper

The repo shows 5,467 commits and a large set of open issues/PRs, so it is active. The quick start scaffolds a sample app. It positions itself next to MCP (agent↔tools) and A2A (agent↔agent).

Tutorial angle: stream tool-call progress and partial answers from a Spring Boot endpoint to a React chat component.

npx create-ag-ui-app my-agent-app

📚 Learn this today

Learn today: OAuth 2.1-style security for Spring — PKCE everywhere, short-lived JWTs, RFC 9700 and RFC 8725

30–40 minutes · reading + one config change

Skim RFC 9700 (OAuth 2.0 Security Best Current Practice) and RFC 8725 (JWT best practices), then audit one Spring Boot resource server: allowed algorithms, token lifetime, where tokens are stored in your React app, and whether PKCE is used for public clients.

💡 Why it matters to you: Auth is the area where small mistakes become incidents — and it ties to your Spring Security + JWT work, plus this week's fix for JWT rejection with empty issuer-uri in Boot 4.1.2.
Read deeper

Search-result summaries of the standards agree on the practical rules: use PKCE for all OAuth clients and drop the implicit flow; prefer asymmetric algorithms such as ES256/RS256 and reject the 'none' algorithm; keep access tokens short (roughly 5–15 minutes); prefer HttpOnly cookies over localStorage for browser tokens; consider passkeys (WebAuthn) as the primary login. OAuth 2.1 itself is described as a consolidation of this guidance — check the IETF datatracker for its current status before citing it as final.

Checklist for your project: (1) which signing algorithm does your issuer use? (2) what is your access-token TTL and how are refresh tokens rotated? (3) does your React app avoid storing tokens in localStorage? (4) are redirect URIs exact-match? (5) is `iss` validated?

spring.security.oauth2.resourceserver.jwt.issuer-uri=https://idp.example.com/realms/demo
# Spring validates the signature (via JWKS), the issuer and the expiry by default
