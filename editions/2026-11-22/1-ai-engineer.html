Model releases and pricing

Claude Fable 5.2 and Mythos 5.2: one model, two access tiers, $8 / $40 per million tokens

Anthropic · Nov 9, 2026

Anthropic launched Claude Fable 5.2, the general-availability version, and Claude Mythos 5.2, the same underlying model for vetted organisations with fewer cyber and biology blocks. Standard pricing is $8 input and $40 output per million tokens, with a fast mode at $16 / $80 that is up to 2.5x quicker. Anthropic says outputs are up to 30% faster than 5.1 and still recommends Opus 5.5 for most daily work.

💡 Why it matters to you: The API ID is claude-fable-5-2, so you can point a Spring AI Anthropic or LangGraph agent at it today. The price is high enough that you should route only your hardest agent steps to it.
Read deeper

On Anthropic's own table Fable 5.2 scores 49.1% on FrontierCode 2.0 (Xhigh), 69.9% on FrontierSWE v2, 74.6% on Terminal-Bench-Science 0.1 and 89.3% on a partial OSWorld 2.1 run. Those beat Fable 5.1 and the listed Opus 5.5, GPT-6 Astra and Gemini 4 Carbon on most rows, but Gemini 4 Carbon leads AutomationBench (53.9% vs 51.4%). These are vendor-reported numbers, so run your own evals before switching.

Safety behaviour matters for tool builders. Fable's classifiers block high-risk cyber work (penetration testing, exploit generation) and most research biology, and blocked requests fall back to Opus 4.8 (cyber) or Opus 5 (biology). Preserved thinking now applies to all API accounts. Fable 5.2 is available on AWS, Google Cloud and Microsoft Azure as well as the Anthropic API.

GPT-6.2 Astra and Sol: OpenAI splits a heavy model and a cheap one, Astra at $8 / $40

OpenAI launch via LetsDataScience, DataCamp and llm-stats · Nov 17, 2026

OpenAI released GPT-6.2 Astra for demanding work and GPT-6.2 Sol for everyday tasks, both in ChatGPT and the API and both accepting text and images. Secondary coverage lists Astra at $8 input and $40 output per million tokens, about 20% below GPT-6 Astra, and Sol at $2 / $10. I could not open OpenAI's own launch page, so confirm prices there.

💡 Why it matters to you: Sol is the one to test first for a Java back end: it is reported to score close to Astra on FrontierCode 2.0 at roughly a fifth of the cost per task.
Read deeper

Reported numbers: on FrontierCode 2.0 Sol scores 43.8% at $1.29 per task and Astra 44.2% at $5.97. Astra reaches 77.1% on Terminal-Bench-Science 0.1. On the Artificial Analysis Intelligence Index, a third party aggregate, Astra scores 62 and Sol 57 against 65 for Claude Fable 5.2. Cached input is listed at $0.40 for Astra and $0.10 for Sol, requests above 272,000 input tokens cost more, and Batch is 50% of standard.

Sources disagree on the prior GPT-6 Astra price ($10 / $50 in one table) and on competitor naming, so treat the "20% cheaper" claim as unverified until you check OpenAI's pricing page. Tooling already followed: Codex CLI 0.171.0 made Sol the default, and Pydantic AI 2.70 added gpt-6.2-sol and gpt-6.2-astra.

Qwen4-Max arrives closed and API-only, with open Qwen4 weights promised

Constellation Research, LetsDataScience, eWeek · Nov 16, 2026

Alibaba released Qwen4-Max, its largest model at 2.4 trillion total parameters, as an API-only product with no public weights. It has said smaller open-weight Qwen4 models will follow without giving a date. The most recent confirmed open release I found is Qwen3.8-27B under Apache 2.0.

💡 Why it matters to you: If you plan to run a Chinese open model locally through Ollama, Qwen3.8-27B is the usable one today; Qwen4 open weights are a promise, not a download.
Read deeper

The licence split is the story: the Max line is closed or restricted, while the mid-size models stay open. One blog claims Apache 2.0 weights by December 20, but that post looked unreliable, so do not plan around that date.

Local-speed data from a November 16 test (Qwen3.8 27B, Q3 quant) showed about 15 tokens per second on a 128 GB Ryzen AI Max+ 395 across Ollama, LM Studio and llama.cpp, so a 27B model is realistic on a well-equipped desktop.

MCP and protocols

MCP Java SDK 2.2.0 adds a stateless server and client for the 2026-07-28 spec

modelcontextprotocol/java-sdk · Nov 16, 2026

Version 2.2.0 introduces a stateless server and a client for the 2026-07-28 MCP revision in a new io.modelcontextprotocol.modern package; the legacy client and server are unchanged. It deprecates the APIs that initiate roots, sampling and logging, though handler registration stays. There are breaking changes in McpTransportContext and several preview APIs.

💡 Why it matters to you: This is the SDK Spring AI's MCP support builds on, so it tells you what your Spring Boot MCP servers will look like once you move to stateless mode.
Read deeper

The milestones show the path: 2.2.0-M1 (Oct 16) was the first sessionless server, M2 (Nov 13) added required-capability enforcement and SEP-2243 Mcp-Param header validation, and GA followed on Nov 16. McpParamHeaders was replaced by McpHeaders, and McpTransportContext no longer uses content-based equals and hashCode, so audit any code that used it as a map key.

Spring AI 2.1.1 (December) is planned to add STDIO and WebClient MCP client transports, and the team is exploring serving both legacy and modern protocol versions from one server.

Reference MCP servers 2.2 to 2.5: three weeks of security fixes in git, filesystem and fetch

modelcontextprotocol/servers releases · Oct 28 to Nov 18, 2026

The official reference servers shipped four releases in three weeks, mostly security work. 2.5.0 (Nov 18) fixes eight vulnerabilities across mcp-server-git, server-filesystem and server-everything, and 2.4.0 (Nov 11) fixes six across filesystem, git and fetch. 2.3.0 added git_merge, append_file, copy_file and an --allowed-hosts allowlist for fetch.

💡 Why it matters to you: If your Claude Code or Cursor setup uses the git, filesystem or fetch MCP servers, update them now and use the new --read-only and --allowed-hosts options.
Read deeper

Fixes include confining git --repository access through alternates, linked worktrees and symlinks, refusing index entries that point outside the working tree, anchoring filesystem directory listings, and treating IPv6 site-local addresses as private in fetch. Known gaps remain: a Windows directory junction is not yet covered, and the git --repository check is not repeated after a write.

2.2.0 (Oct 28) responded to an October eMudhra CA compromise and Node.js releases: use Node 24.22.1 or 26.12.1 or later and refresh mcp-server-fetch with uvx --refresh.

# refresh the Python fetch server so it picks up the new CA bundle
uvx --refresh mcp-server-fetch

AG-UI and A2UI 1.0: protocols that let an agent drive your React interface

CopilotKit, Google Developers Blog, GitHub trending · A2UI 1.0 reported Nov 2026

AG-UI is an open MIT-licensed transport between a user-facing app and an agent backend, and A2UI is Google's payload format in which an agent emits JSON describing interface surfaces that the front end renders with its own components. CopilotKit sits on top as the React and Angular layer. The AG-UI repo gained about 3,800 stars this week on GitHub trending.

💡 Why it matters to you: This is the missing front half of your stack: a Spring AI or LangGraph agent in the back, a React component set in the front, and a standard protocol between them.
Read deeper

One source describes the loop as: A2UI describes it, AG-UI carries it, CopilotKit renders it, and user actions go back to the agent. You can also consume the stream directly with @ag-ui/client and hand A2UI operations to a renderer such as @a2ui/react.

Most write-ups come from CopilotKit and partners, and the categorisation of the layers differs between sources (MCP Apps and Open-JSON-UI are alternatives). Check current docs before relying on version details.
