AI tools of the day

Tool: ffmpeg-skill, a local video editor your coding agent can drive

kajisho5/ffmpeg-skill · trending on GitHub this week (about 3,600 stars gained; 9.3k total, MIT)

ffmpeg-skill gives Claude Code, Cursor and Codex 42 FFmpeg tools (cut, join, silence removal, captions, loudness, export and more) with a machine-readable contract and an MCP server. It runs locally with no cloud and no API keys, on Python's standard library plus FFmpeg.

💡 Why it matters to you: As a tutorial creator you can ask your agent to cut dead air, add captions and normalise loudness on a screen recording, instead of doing it by hand.
Read deeper

Setup is npx ffmpeg-skill setup, which installs the skill for detected agents, installs FFmpeg if missing and runs a doctor check. By default the MCP server advertises a core 12 tools; set FFMPEG_SKILL_MCP_FULL=1 to list all 42. It needs Node 16+ and Python 3.10+.

Try it on a throwaway recording first: any tool that edits media can overwrite files, so keep originals.

npx ffmpeg-skill setup

{"mcpServers": {"ffmpeg-skill": {"command": "python3", "args": ["/Users/you/.claude/skills/ffmpeg-skill/mcp/server.py"]}}}

Tool: last30days-skill, a research brief ranked by upvotes and real money

mvanhorn/last30days-skill · trending on GitHub this week (about 4,200 stars gained; 72.0k total, MIT)

last30days is an agent skill that researches a topic across Reddit, Hacker News, Polymarket and GitHub with no setup, and optionally X, YouTube, TikTok and more with keys. It returns one ranked, cited brief that merges duplicate stories across platforms.

Output can be saved as Markdown, JSON or SQLite. Check what each source does with your queries before you run it on private topics.

Tool: Plannotator, annotate an agent's plan or diff and send feedback back

backnotprop/plannotator · trending on GitHub TypeScript this week (about 3,400 stars gained; 14.2k total, Apache-2.0 or MIT)

Plannotator is a local, browser-based review workspace for AI coding agents. When an agent reaches its plan-approval step, a hook opens a review UI where you annotate and approve or deny with structured feedback, and you can annotate local diffs and remote pull requests the same way.

💡 Why it matters to you: It gives you a real review loop for Claude Code or Codex runs on your Spring and React repos, instead of reading a wall of terminal output.
Read deeper

It supports Claude Code, Codex, Copilot CLI, Gemini CLI, OpenCode, Kiro, Droid, Amp and Pi through plugins, hooks or commands. For code review you run /plannotator-review, annotate the diff and send comments to the agent session. Each agent needs its own follow-up install step.

Repo: openai/codex-security, find, validate and fix vulnerabilities with an agent

openai/codex-security · trending on GitHub (about 770 stars gained this week; 14.3k total, Apache-2.0)

Codex Security is a CLI and TypeScript SDK for finding, investigating and fixing vulnerabilities. It scans repos, paths or Git diffs in Standard or Deep mode, validates findings, generates patches, drafts a SECURITY.md and exports threat models, with SARIF, JSON or CSV output.

💡 Why it matters to you: Run it on a Spring Boot repo after reading Java4Shell and the Maven advisories, and compare its findings with your SCA tool.
Read deeper

It needs Node 22.13+ (22.x, 24.x or 26.x) and Python 3.10+, and supports OpenAI, Amazon Bedrock, OpenRouter and Fireworks. A GitHub Action can scan weekly using an OpenAI API key stored as CODEX_SECURITY_API_KEY. The README did not list supported languages, so test it on your stack before trusting it.

Scans send code to a model provider, so check your policy before pointing it at client repositories.

npm install --global @openai/codex-security
cs login
cs scan . --diff origin/main

Idea: a "JVM fleet checker" that flags Java4Shell-exposed Spring Boot services

Inspired by CVE-2026-114938, disclosed Nov 17, 2026

Build a small Spring Boot and React dashboard that records each service's Java runtime version (from Actuator info or a startup report) and compares it with a list of fixed builds. It shows red, amber and green per service and suggests the Jib or Docker rebuild.

💡 Why it matters to you: It is a timely, teachable security project that uses skills you already have.
Read deeper

Start with a JSON file of fixed versions (one source lists 17.0.21.1, 21.0.13.1, 25.0.5.1 and 27.0.1.1, but verify per vendor). Add an endpoint that your services post to on startup, store results in Postgres, and use a Spring AI Decision Model to draft the remediation ticket text. A video on "how I found every vulnerable JVM in my own projects" would fit the creator side.

Learn this today

Learn today: write your first Agent Skill (a SKILL.md) and install anthropics/skills

anthropics/skills (about 198.5k stars, trending this week) · Agent Skills donated to the Agentic AI Foundation Oct 22

An Agent Skill is a folder with a SKILL.md file: YAML frontmatter with a name and description, then Markdown instructions the agent loads when relevant. The anthropics/skills repo holds examples, the spec and a template, and you can add it to Claude Code as a plugin marketplace.

💡 Why it matters to you: You can package your own Spring Boot or React conventions as a skill, and it makes a good tutorial topic.
Read deeper

Only two frontmatter fields are required: name (lowercase, hyphens) and description (what it does and when to use it). A good description is what makes the agent pick the skill, so write it like a trigger. Install the examples with /plugin marketplace add anthropics/skills, then /plugin install example-skills@anthropic-agent-skills.

The repo says its skills are for demonstration, so test them before relying on them for real work. Anthropic donated the Agent Skills standard to the Agentic AI Foundation on Oct 22, and the MCP TypeScript SDK 2.4 can serve skills over MCP.

---
name: spring-boot-conventions
description: Use when writing or reviewing Spring Boot code in this repo. Covers package layout, DTOs and test style.
---

# Spring Boot conventions

- Controllers return DTOs, never entities.
- Use constructor injection.
- Add a Testcontainers test for every repository.
